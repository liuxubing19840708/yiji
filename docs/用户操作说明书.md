# 用户操作说明书（衣计 · 服装计件生产管理）

> 适用人员：服装厂**一线工人、仓管、跟单、工艺/生产负责人、车间主任、工厂管理员、老板和会计**。
>
> 版本日期：**2026-11-15**。本文按当前小程序页面、Web 工作台和后端业务规则重新整理；按钮名称或位置可能随发布版本调整。
>
> 使用原则：先选对**当前公司**，再按本人岗位权限操作。后端保存的数量、金额、库存和状态才是正式结果，页面预览、截图、打印记录和暂存数据不能代替业务凭证。

---

## 一、先读这一页

### 1.1 完整业务顺序

```text
账号建厂 → 岗位与员工 → 客户/工序/款式/工艺/BOM
→ 报价与订单 → 产前准备
→ 采购/暂收IQC/入库/库存/领退料
→ 开床编菲/生产路线 → 报工/质检/返修/责任交接/外发
→ 包装/成品入库 → 出货/应收/收款核销
→ 工资结算/工资条/工资实付
→ 采购应付/供应商付款/其他收支/经营现金流
→ 成本利润/看板/通知/导出/审计
```

不要跳步：例如，扫菲报工不等于质检合格，质检合格不等于包装审核，包装审核不等于成品入库，成品入库后才形成可出货现货；出货审核生成应收，应收不等于已收款；工资结算不等于工资已支付，采购入库也不等于已经建立或支付应付。

### 1.2 常见概念

| 名称 | 正确理解 |
|---|---|
| 菲票 | 一扎产品的追溯依据，记录床次、扎号、颜色、尺码、数量等；不是逐件唯一序列号 |
| 报工量 | 员工完成某工序的计件登记，是计件和工序进度依据 |
| 节点合格量 | 经对应质量动作或检验确认形成的合格数量，不自动等于报工量 |
| 生产在手 | 路线中尚未转出、报废或形成后续有效结果的数量，以节点余额和统一流水为准 |
| 成品现货 | 有效成品入库减有效出货后的可交数量，不是报工累计量 |
| 结算 | 把某期间工资形成快照；结算后相关登记不能随意撤销 |
| 实付 | 实际向员工支付工资的事实记录，需要支付时间、方式和外部流水号 |
| 应收/应付 | 应向客户收取/应向供应商支付的账款，不等于现金已经到账或支出 |
| 撤销/冲销/作废 | 不同业务的纠错方式，都会保留必要历史；不能直接改数据库或删除已审核事实 |

### 1.3 验证边界

本文是操作说明，不是真机或外部服务验收报告。真实摄像头、蓝牙物理出纸、真实短信、微信登录/订阅消息、语音识别、真实 GLM 和外部支付渠道，仍须在目标环境与设备上验收。后端自动化通过、微信开发者工具编译通过或页面显示“成功”，均不能替代这些现场验收。

## 二、登录、建厂与岗位准备

### 2.1 登录与切换公司

1. 打开小程序「衣计」，选择验证码登录、密码登录或微信一键登录，并同意隐私政策与用户协议。
2. 验证码登录须由部署方配置真实短信服务；未配置时使用已分配的密码或微信登录，不使用任何文档中的演示账号。
3. 在多家公司任职时，选择本次要操作的公司。
4. 后续换厂：底部〔我的〕→〔切换公司〕→ 选择在职公司。换厂后重新核对首页数据、员工、订单和单号。
5. 没有公司时，可输入管理员提供的公司编号申请加入，等待审核；也可创建公司并成为管理员。

Web 工作台使用部署方提供的 `/web/` 地址，支持密码、短信验证码及已配置的微信网页 OAuth，登录后使用相同公司选择流程，左上角可切换工厂。开发地址、隔离数据库和测试账号不得用于正式业务。

### 2.2 认识小程序

- 底部：**首页 / 扫菲 / 通知 / 我的**，中央为 **AI问报**。
- 首页宫格：订单、生产、仓库、交接、薪酬、财务等入口按当前公司岗位权限显示。
- 「工序」在首页宫格，不是底部页签。
- 普通员工通常只看到基础入口；口头职务不会自动带来管理权限。
- 找不到入口时，先核对当前公司，再由管理员检查岗位授权，不要借用他人账号。

### 2.3 建厂后的基础资料

建议由管理员按以下顺序准备：

1. **员工与岗位**：员工管理 → 邀请/审核员工 → 岗位管理 → 按职责授权 → 设置工资方式和指定工序。
2. **客户与供应商**：分别维护客户、供应商编码及联系资料；被业务单引用的资料不能随意删除。
3. **工序与工价**：维护固定工序、默认价、工序模板；款式/床次/订单按实际工艺配置价格和顺序。
4. **款式**：填写款号、名称、客户、图片和工艺说明，可上传工艺图片和产品视频。
5. **物料与 BOM**：建立物料主档，按款式建立 BOM 草稿、填写净用量和损耗率，再激活生效。
6. **生产路线**：需要节点级质量、交接、包装和成品控制时，先维护阶段和模板，再绑定订单或床次创建实例。

权限应最小化：查看用 `view`，新建、审核、收付款等操作用 `manage` 或专项权限。隐藏按钮不是安全控制，后端仍会校验公司成员身份和权限。

## 三、工人：扫菲、报工与个人工资

### 3.1 扫菲登记

1. 点底部〔扫菲〕，用摄像头扫描二维码，或从相册识别。
2. 扫码失败时选择〔手输查找〕，输入床次号和扎号，选择正确菲票。
3. 核对款号、床次、扎号、颜色、尺码和扎数量，选择本人实际完成的工序。
4. 核对本次数量；确需修改时展开数量输入，再点〔确认登记〕。
5. 成功后核对今日件数和预估工资。双击款号可查看款式图、工艺说明和产品视频。

登记数量受扎数、前道必过工序、床次锁定和工价配置约束。同扎同工序是所有员工累计封顶，不是每人都能登记一整扎。

### 3.2 弱网与待同步

网络异常时，符合离线条件的登记可能暂存本机。扫码页出现「本地待同步登记」时：

- 暂存不代表服务端已入账，不计作正式产量和工资。
- 网络恢复后打开待同步列表并手动重发，逐条检查结果。
- 超量、床次锁定、未上价等业务错误必须修正原因，不能靠反复重发解决。
- 未处理完前不要换手机、退出账号或清理小程序数据。

### 3.3 撤销错误登记

在首页〔我的登记/工作中〕找到记录并撤销：

- 本人通常只能撤销本人当天登记；跨日或跨月限制以工厂规则为准。
- 已结算登记不能撤销，须由管理员先处理结算关系。
- 撤销是整笔回退；数量只错一部分时，撤销后按正确数量重新登记。
- 管理员代撤也受结算和期间规则限制，不得绕过。

### 3.4 协助扫菲与批量代登

- **协助扫菲**：选择当前公司在职员工后进入扫菲，确认页面显示“正为某员工登记”，结束后退出协助。
- **批量代登**：选择员工、床次和工序，逐扎填写本次数量。提交后查看逐扎结果；部分成功时只修正失败行，成功行不要重复提交。
- 代登不能绕过数量、前道、价格、权限和公司隔离规则。

### 3.5 我的薪酬与结算申请

- 〔我的薪酬〕按日期、床次或汇总查看工资、计数和固定工资。
- 工资金额按本人工资方式计算；工序计件、整件、提成和固定工资不能自行重复相加。
- 需要结算时提交申请，之后在结算记录中查看审核进度。
- 「已结算」表示形成工资快照；是否实际到账，应查看本人实付记录并核对银行或支付渠道流水。

## 四、跟单与工艺：报价、订单和产前准备

### 4.1 报价管理

1. 新建报价，选择款式、客户、报价数量和日期。
2. 用料可从生效 BOM 带出，也可手选物料，核对单耗和单价。
3. 核对人工工价快照、倍率、小单溢价和附加费，保存报价；系统重新计算合计。
4. 报价详情依次标记已发送、成单或输单。成单/输单是终态，需要重报时新建报价。
5. 成单后关联订单，可在实际成本重算后查看报价假设与实际成本对比。

### 4.2 订单管理

1. 新建订单，选择款式、客户、交期和类型；订单号自动生成。
2. 在数量矩阵中添加颜色、尺码、数量和单价，保存前核对总数量。
3. 关联工序可从模板带出，也可手工添加并填写工价。
4. 订单详情查看完成矩阵、关联床次和交期状态，可开床、编辑、标记完成或取消。
5. 已挂床订单不能删除，只能取消。改价、改状态等留痕可在变更记录查看，不提供通用一键回滚。
6. 下游已有生产或出货事实时，改单会受约束；不要用删除重建掩盖历史。

### 4.3 产前准备

从生产相关页面进入〔产前状态/产前准备〕，选择订单后按四步处理：

#### A. 工艺资料

- 保存工艺包后自动生成纸样编号，上传纸样和工艺单附件。
- 结构化尺寸表通过选择填写尺码、部位、尺寸值、单位及正负公差；尺寸值步长 0.5，公差步长 0.1。
- 工艺要求、工艺难点、易错点和品质标准可选择标准/公司模板，再按本单修改。
- 常用内容可〔存为模板〕，供后续订单快速选择。模板只是起点，本单保存前仍须复核。
- 工艺变更使用〔新建版本〕，可复制当前资料并递增版本；旧审批保留，但不会自动成为新版本的有效审批。

#### B. 产前样

- 先保存工艺资料，再追加合格、不合格或重做等检验结果。
- 检验说明必填，可附样衣图片或附件。
- 每次检验追加历史，不覆盖上一次结果。

#### C. 工艺问题

- 登记问题后，由负责人填写处理结果并解决；需要重新处理时可重开。
- 未解决问题未处理完时，不能把它当作已具备审批条件。

#### D. 交底与审批

1. 生产负责人完成班组交底后，填写说明并确认。
2. 系统列出缺失资料，逐项补齐。
3. 有审批权限的人员对当前订单和工艺版本执行通过或驳回，并保留意见。
4. 新建工艺版本后重新完成必要交底和审批，不沿用旧版本“已批准”的口头结论。

## 五、仓管：采购、IQC、库存与领退料

### 5.1 物料档案与导入

- 新建物料时填写编码、品名、分类、主单位和单价单位；使用副单位时补齐克重、幅宽等换算参数。
- 被 BOM 引用的物料不能删除，可停用；停用物料不用于新单。
- Excel 导入按模板准备 `.xlsx`。任一行失败则整批不生效，修正错误行后重导；已存在编码按更新处理，仍须核对更新内容。
- 上线期初库存没有普通界面入口，由实施方在实盘后协助处理，不要为凑数虚录库存。

### 5.2 BOM

1. 选择款式，新建 BOM 草稿。
2. 添加物料，填写净用量和损耗率，核对定额。
3. 保存并激活；旧生效版自动停用。
4. 修改生效 BOM 时先改版生成新草稿，再激活新版本。

生效 BOM 是领料定额和报价带料依据；历史发料快照与当前 BOM 可能不同，差异报表会分别展示。

### 5.3 采购与暂收 IQC

1. 维护供应商，按需建立采购单。
2. 在〔暂收IQC〕新建暂收单，从采购行带入或手工添加明细。
3. 填写物料、批次、到料量、合格量和拒收量，保留实收与检验依据。
4. 保存后复核，再执行〔确认入库〕。确认后合格量生成采购入库事实，单据只读。
5. 拒收量留痕，不等于合格库存；不要把到料量全部当成可用量。
6. 确认入库后，由财务按**合格入库、采购价格及实际对账结果**建立采购应付；当前入库不会自动替财务决定最终应付金额。

### 5.4 按床领料与退料

1. 选择领料模式和床次，系统按生效 BOM 带出定额。
2. 填写实领数量和批次/缸号，保存并确认。
3. 超领会标记并可填写原因；它不是自动禁止，管理人员应在差异报表跟进。
4. 无生效 BOM 时可按权限手选物料补料，这类记录进入无定额口径。
5. 退料时切到退料模式，选择原床次、物料和批次，数量填正数，保存确认。

已确认单不直接改写。错领通过退料等受控方式纠正，避免库存和床次血缘失真。

### 5.5 仓库、需求与差异

- 轻量仓库用于采购、入库、领料等单据查看和简单补录；日常到料优先走暂收 IQC，日常发料走按床领料。
- 采购需求汇总按需求、库存和在途给出建议采购量；缺少换算参数的数据需先补齐。
- 差异报表对比实领、退回、发料快照定额和当前 BOM 应发，并显示超领、无定额和待补参数。
- 库存估值可按物料和截止日查看批次及加权口径；不同口径不能直接混加。

## 六、车间：开床、路线、报工、质检和交接

### 6.1 开床与菲票

1. 从订单详情开床，或进入生产管理新建床次。
2. 核对款式、订单、颜色尺码、裁货数、工序和工价。
3. 无生效 BOM 时按页面提示处理；确需绕过必须由有权限人员确认并填写原因。
4. 按扎拆分数量并生成菲票，先预览核对，再安排打印和发扎。
5. 「置为裁完」只表示裁剪完成，不阻止后续工序；「锁定床次」才禁止继续登记，需补登时按权限解锁。

### 6.2 生产路线首次配置

1. 在〔全流程生产〕维护标准阶段，如裁床、流水线、半检、专机、整烫、尾查、包装和成品入库。
2. 新建路线模板，按现场顺序添加节点，配置必过、并行和可跳过。
3. 检查缺尾查、包装、成品入库或阶段停用等提醒。提醒不等于所有错误配置都会被强制拦截，管理员仍须核对。
4. 从启用模板创建实例，绑定一个床次或一个订单。只有实例能执行，模板本身不能报工。
5. 选择实例和菲票，核对节点余额后执行动作。

模板编辑、复制、新版本和停用不影响既有实例的节点快照；已被引用的阶段保留历史保护，不直接删除历史模板或实例。

### 6.3 节点动作与流水

- 按现场实际选择首节点接收、完工判合格、合格转出、返修退回或报废。
- 数量必须为正整数，不能超过当前可转量；报废、返修等按页面填写原因。
- 专用节点必须走专用单证：节点质检、裁片交接、包装、成品入库和出货不能用普通备注或通用转出绕过。
- 普通流水冲销新增反向记录并填写原因；业务单证生成的流水须从原单证处理。
- 网络异常后先核对原请求是否生效，再重试，避免重复入账。

### 6.4 节点质检与轻量返修

**节点质检**用于路线放行：

1. 选择检验类型、菲票和节点，填写检验、合格、返修和报废数量。
2. 返修选择回退节点，必要时关联原检验单复检；返修或报废填写原因。
3. 创建待确认检验单，由有权限人员复核后〔确认并记账〕。
4. 只有确认后的检验才作为对应质量放行依据。

**轻量返修**用于“登记返修 → 收货 → 完成”的简单闭环，不等同于完整来料检、巡检、AQL 或成品检验。返修完成也不能单独证明整单质量合格。

### 6.5 责任交接

交接用于留下“谁交出、谁接收、交多少、实收多少、何时处理、有何差异”的证据，减少裁床与多个车间/班组之间扯皮。

#### A. 先配置策略

在〔交接中心 → 策略〕维护公司默认规则，必要时新增节点覆盖规则：

| 模式 | 用途 |
|---|---|
| off | 不强制交接，适用于风险低或暂不需要签收证据的环节 |
| warn | 超时提醒但不阻断，适合先培养签收习惯 |
| strict | 阻断绕过交接的普通裁片转出；正常交接接收仍可完成 |

可配置超时时间，并按交出节点、接收节点、目标组或指定接收人设置更具体规则。越具体的规则优先。节点 ID、组号或用户 ID 应从本公司真实资料核对，不要凭猜测填写。超时通知依赖服务端计划任务，每位相关接收人每天最多一条。

#### B. 一对多发起

1. 从裁床等业务页选择菲票、交出节点、接收节点和接收目标，进入交接发起页。
2. 一个裁床可分给多个负责人或班组。每个接收目标独立分配菲票和数量，不能重复预占同一数量。
3. 核对目标数、菲票总数和应交总量，填写备注后批量发起。
4. 系统生成一个批次和多张独立交接单；每张单由各自接收人处理，互不要求“所有人同时接收”。
5. 从批次汇总查看各目标进度，不要把一张单的接收当作整批全部完成。

#### C. 接收、差异、拒收和改派

- 数量一致：在〔待我接收〕打开单据，点〔全部接收〕。
- 短少、多出或破损等：选择〔有差异，逐项登记〕，填写实收数量、差异类型和原因，再确认。未展开的差异项按全收处理。
- 不应接收：点〔拒收〕并填写具体原因，交出人根据现场结果重新处理。
- 接收人变更：有权限人员执行〔改派〕，填写本公司在职成员用户 ID 和原因。
- 详情中的操作记录保留操作账号、实际责任人、时间和原因。超时单应尽快接收、拒收或改派，不要长期挂起。

### 6.6 外发管理

1. 新建外发单，选择外协供应商和可选款式，填写数量、加工单价、工序和交回日期。
2. 分批收回时登记本次数量，状态从已发出到部分收回、已收回。
3. 全部收回后按权限结算，保留加工费对账依据。

当前外发是轻量加工往来：不自动生成采购应付，不自动进入订单外发成本，也不是完整委外发料、退料和物料结存三账。财务和管理员须另行核对，不得把成本页外发为 0 解释为没有费用。

### 6.7 包装、成品入库和出货前置

1. 包装单审核形成包装合格数量，但尚不增加成品现货。
2. 从有效包装单创建成品入库单并审核，才形成有效入库。
3. 出货只能使用有效成品现货，不能用报工量或质检合格量代替。
4. 后续已有有效入库或出货时，前置包装/入库不能直接冲销；按出货 → 入库 → 包装的受控顺序处理。
5. 冲销必须填写原因，原单和原流水保留，已冲销单不能重新审核或重复冲销。

## 七、出货、应收与客户回款

### 7.1 出货管理

1. 新建出货单，选择订单、客户、交货/发货日期，核对颜色、尺码、数量和未交量。
2. 草稿可编辑；审核前检查色码单价、成品现货和订单可交量。
3. 审核后扣减有效成品现货并自动生成应收，状态为全部出货或部分出货。
4. 按实际装箱维护箱号、色码、件数、毛净重和箱规，可打印出货单或装箱单。
5. 已审核单不能删除，只能作废；草稿才可删除。可补录物流单号、发货日期和备注。
6. **出货作废不自动撤销应收**，须在应收管理按实际资金关系另行处理。

### 7.2 应收与核销

- 列表查看应收、已收、剩余和状态，可筛选未收、部分收款和已结清。
- 单笔收款：进入应收详情 → 收款核销 → 填写本次金额、方式、经手人和备注。累计核销不能超过应收。
- 客户批量收款：选择客户并填写到账总额，系统按应收创建时间从最早开始分配（FIFO）；提交后逐单核对分配结果。
- 撤销收款会回退相应已收金额并重算状态；操作前核对原银行到账，不能重复登记同一笔款。
- 应收作废前先处理全部有效收款，按页面规则执行。导出文件不是银行到账凭证。

## 八、薪酬：结算、工资条与实付

### 8.1 工资设置与结算

1. 在员工管理中设置工序计件、整件计件、计件提成或固定工资，并维护指定工序。
2. 在〔薪酬管理〕选择期间，核对员工工资金额。
3. 进入〔结算与发放 → 工资结算〕，确认该期间快照。
4. 结算后相关登记不能随意撤销；确需纠错时先核对实付和结算状态，再按可用规则撤销结算。
5. 在结算记录中查看工资条和员工明细，处理员工结算申请审核。

旧“申请发放”记录与新的工资实付事实不是同一概念。实际资金管理应以工资实付记录、外部流水和经营现金流为准。

### 8.2 登记工资实付

入口：〔薪酬管理 → 结算与发放 → 工资实付与结算分摊〕。

1. 点〔登记实付〕，选择员工。
2. 填写实付金额、实际日期和时分、支付方式及**真实外部流水号**。
3. 选择结算归属：
   - **分摊到已有结算单**：可添加多张结算单，每张分摊不超过该员工当前可付余额；分摊合计必须等于本次实付金额。
   - **无结算支付**：不抵扣任何结算单，只记录实际支付事实，适用于确有依据的非结算支付。
4. 核对员工、金额、期间和流水号后提交。后端按提交时的有效支付重新核算余额，防止超额或重复支付。
5. 员工和会计可在详情查看支付事实、操作人及各结算分摊后的已付/未付金额。

没有全员薪酬查看权限的员工只能看本人实付，不能替他人登记。登记实付通常需要 `salary.manage` 或 `salary.review`，查看全员还需要 `salary.view`。

### 8.3 工资支付作废与重新支付

- 实付记录不可编辑或删除。登记错误时只能填写作废原因后作废。
- 作废后，该支付不再抵扣结算余额，相应未付余额恢复；支付和分摊历史仍保留，且作废不可恢复。
- 如果实际已重新付款，新建一笔实付并填写新的真实流水号，不要恢复原记录或重复使用流水。
- 作废不等于银行自动退款；资金是否退回必须在线下渠道核对。

## 九、会计：应付、供应商付款与经营现金流

入口：首页宫格〔资金管理〕。页签包括**采购应付、供应商付款、其他收支、经营现金流**；经营现金流还受薪酬查看权限控制。

### 9.1 建立采购应付

1. 根据采购、暂收 IQC、合格入库、价格和供应商对账单确认最终应付金额。
2. 在〔采购应付〕点〔新建应付〕，选择供应商或填写名称，录入金额、应付日期、可选到期日和备注。
3. 保存后核对 AP 单号、应付、已付和未付余额。
4. 当前入库不自动生成最终应付，仓管确认数量与财务确认金额是两个步骤。
5. 应付存在有效付款时不能作废；先按事实作废相关付款，再处理应付。作废保留审计，不应为改金额而随意作废正确单据。

### 9.2 登记供应商付款

1. 在〔供应商付款〕点〔登记付款〕。
2. 选择要核销的未结应付；选择后核对供应商和未付余额。
3. 填写实际付款金额、日期、方式、外部流水号和备注。关联应付时累计有效付款不能超过应付金额。
4. 部分付款后状态为部分付款，付清后为已结清。
5. 确有无应付关联的实际付款时，可选择独立付款，但必须保留供应商和付款依据；它不会自动冲减某张应付。
6. 付款错误时填写作废原因后作废。关联付款作废会回退应付已付金额、恢复未付余额；原付款记录保留。

### 9.3 其他收支

用于房租、水电、利息等未由客户回款、工资实付或供应商付款自动承载的实际收支：

1. 选择费用支出或其他收入。
2. 填分类、实际金额、业务日期、收付方式，可填往来对象和外部单号。
3. 保存后如需纠错，填写原因作废，不修改或删除原流水。
4. **不要重复登记**：客户回款、工资实付和供应商付款已经由各自事实表进入经营现金流，不能再手工录一笔同额费用/收入。

### 9.4 经营现金流

1. 选择日期范围，按日或按月查询。
2. 查看流入、流出和净现金流，以及客户回款、其他收入、实付工资、供应商付款和费用明细。
3. 统一现金流只统计有效事实；工资支付、供应商付款和其他收支作废后，不再计入有效现金流。
4. 应收、应付是债权债务，不等于现金流；只有实际收款和付款进入现金流。
5. 现金流按业务发生时间汇总，不等于银行余额。对账仍须核对银行、现金和支付渠道。
6. 查看完整经营现金流需要 `finance.manage` 与 `salary.view`，避免仅财务权限泄露员工工资金额。

### 9.5 成本与订单损益

- 成本管理按订单展示理论收入、材料、人工、外发、制费、总成本和毛利；单据变化后执行重算。
- 缺价批次和未归属订单的床次应单独处理，不能为得到“好看”的利润虚填价格或挂错订单。
- 订单损益可比较理论口径和实收口径；汇总条若只覆盖当前已加载行，不得当作全厂合计。
- 外发尚未自动接入订单成本；固定工资、整件/提成与订单人工也不保证自动全部分摊。
- 成本、订单损益、工资对账、应收应付和现金流各有口径，重要决策应交叉核对原始单证。

## 十、看板、问报、通知、导出与审计

### 10.1 生产与运营看板

- 生产看板用于计划、订单、床次、组/人及今日登记等视角。
- 全流程生产的流程看板用于单路线节点余额、待办和流水核查。
- 运营看板跨订单、跨床次查看生产在手、累计报废、成品现货、交付和待办。
- 滞留指节点仍有在手且最后流水活动早于所选阈值。顶部指标汇总全部筛选路线，表格分页显示；“只看滞留”当前作用于已加载的本页。
- 看板用于定位问题，最终处理须回到具体菲票、路线和单证。

### 10.2 AI 问报

- 可询问产量、订单进度、薪酬、应收应付、供应商付款和经营现金流等受控数据集。
- 数字由后端按当前公司、期间和权限计算，不应由模型凭空估数。
- 未配置真实 GLM 或外部服务失败时，不等于数据已核实；可按页面提供的本地快捷问题操作。
- 语音识别后先检查文字再发送；重要金额回到业务页面复核。

### 10.3 通知、导出与日志

- 通知页查看本人消息；入职、结算、交接超时等待办按权限处理。超时通知依赖服务端计划任务正常运行。
- 导出 XLSX 后实际打开检查筛选范围、中文、金额和分页/汇总口径；导出文件不是外部凭证。
- 日志管理按日期和类型查看操作人、目标员工、时间和消息。交接详情另有完整事件记录。
- 日志用于追溯，不提供任意篡改或删除历史事实的入口。

## 十一、打印与标签

1. 小程序在打印管理中开启手机蓝牙和微信权限；Web 使用支持 Web Bluetooth 的 Chrome/Edge，在 HTTPS 或 localhost 下选择并授权正确打印机。
2. 设置纸张、二维码、字号、字段和上下偏移，换机或换纸后重新试打。两端均可从真实床次菲票生成中文标签；Web 使用浏览器 Canvas 生成 203 dpi 中文位图，具体打印机兼容性以现场为准。
3. 菲票打印失败可在打印队列或历史中重打/补打，出货单在详情使用相应打印入口。
4. 重复打印可能标记补打；补打不等于重复报工，但纸质标签须妥善管理，避免错扎使用。
5. 云打印平台当前未接入，页面路由名或“即将支持”不能当作可用功能。
6. 软件显示已连接、预览成功、打印成功或写入历史，都不证明已物理出纸。现场必须检查实际标签并用另一台目标手机回扫。

## 十二、常见问题与异常处理

| 问题/提示 | 正确处理 |
|---|---|
| 找不到功能入口 | 核对当前公司，再由管理员检查岗位和 `view/manage` 权限；不要借用他人账号 |
| 摄像头不能扫码 | 检查微信摄像头权限、光线和二维码；可手输床次/扎号。开发者工具成功不代表真机成功 |
| 登记提示超扎数 | 查看该扎该工序全员工累计量，只补剩余量；批量代登只重试失败行 |
| 前道必过工序未完成 | 先完成真实前道，或由管理员核对路线/跳序配置；不要代登绕过 |
| 工序未上价 | 核对床次工序价、款式工序价和默认价；历史登记保留原价快照 |
| 床次已锁定 | 由生产负责人确认后解锁补登；裁完不等于锁定 |
| 登记已结算不能撤 | 先核对结算和有效实付，再由管理员按受控流程处理 |
| 暂存一直未同步 | 恢复网络后手动重发并看逐条原因；业务拒绝不是网络重试能解决的 |
| 无生效 BOM | 在 BOM 管理建立并激活对应款式版本后再开床/按定额领料 |
| 领料确认后填错 | 不直接改已确认单，按实际退料或受控纠错 |
| 暂收确认后需修改 | 已确认入库事实不能直接改；联系仓管和财务按库存、应付影响处理 |
| 出货提示超未交量 | 减少本单对应色码数量，核对同订单累计已出货量 |
| 出货提示成品库存不足 | 核对有效包装、入库和出货；不能只用报工量补库存 |
| 出货审核提示色码未定价 | 回订单补齐对应色码单价，再审核生成应收 |
| 收款/付款超额 | 核对原单余额和有效流水，按真实未收/未付金额登记，不虚增单据 |
| 工资实付分摊不一致 | 调整各结算单分摊，使合计等于实付，且每项不超过该员工可付余额 |
| 外部流水号已存在 | 先查原支付是否已生效，不重复提交；若确实重新付款，使用新的真实流水 |
| 付款/支付登记错误 | 填写作废原因后作废，再按真实事实新建；不能编辑删除原流水 |
| 应付不能作废 | 检查是否仍有有效供应商付款，先按实际关系处理付款 |
| 交接长期待接收 | 联系接收人清点并接收、拒收或改派；检查超时通知计划任务 |
| 交接提示数量已被预占/超出 | 查看同菲票其他待接收单和批次，重新分配未占用数量，不重复发起 |
| strict 下普通转出被拒绝 | 走真实裁片交接并由接收方处理，或管理员评审策略，不借权限绕过 |
| 路线没有实例或菲票 | 先建阶段/模板并实例化到订单或床次，再完成对应床次编菲 |
| 有合格量却不能包装/出货 | 核对专用质检确认、包装审核和成品入库审核，不混用数量口径 |
| 外发结算后成本仍无费用 | 这是当前集成边界，按外发单另行对账，不以成本页的 0 作为无费用证明 |
| 打印成功但没出纸 | 检查蓝牙、纸张、设备和偏移，重打并抽扫；打印历史不是出纸证明 |
| 数据表不存在或迁移异常 | 停止操作，记录完整错误并联系实施方；不要自行删除、重建或清空业务库 |

排障时请保留：当前公司、账号、完整提示、订单/床次/扎号/单号、操作时间和必要的界面截图。不要在问题不明时连续重复提交收款、付款、报工或审核。

## 十三、状态速查

| 对象 | 主要状态 | 说明 |
|---|---|---|
| 订单 | 生产中 / 已完成 / 已取消 | 已挂床订单只能取消，不能删除 |
| BOM | 草稿 / 生效 / 已停用 | 生效版用于定额和报价带料 |
| 报价 | 草稿 / 已发送 / 已成单 / 已输单 | 成单、输单为终态 |
| 暂收/IQC | 草稿 / 已确认 | 确认后合格量形成入库事实 |
| 工人登记 | 正常 / 已结算 / 已撤销 | 已结算登记受撤销限制 |
| 路线检验 | 待确认 / 已确认 | 确认后才作为质量放行依据 |
| 交接单 | 待接收 / 已接收 / 已拒收等 | 差异、改派和操作事件保留；以详情状态为准 |
| 包装/入库 | 待审核 / 已审核 / 已冲销 | 冲销保留原单和反向流水 |
| 出货 | 草稿 / 全部出货 / 部分出货 / 已作废 | 审核生成应收，作废不自动撤应收 |
| 应收 | 未收 / 部分收款 / 已结清 | 由有效核销金额计算 |
| 应付 | 未付 / 部分付款 / 已结清 | 由有效供应商付款计算 |
| 工资结算 | 有效 / 已撤销 | 是否可撤销受有效实付等关系约束 |
| 工资实付 | 有效 / 已作废 | 不可编辑删除；作废恢复结算未付余额 |
| 供应商付款/其他收支 | 有效 / 已作废 | 作废留原因，并退出有效现金流 |
| 轻量返修 | 返修中 / 已收回 / 已完成 | 不等于完整质量检验体系 |
| 外发 | 已发出 / 部分收回 / 已收回 / 已结算 | 不自动生成应付或订单成本 |

## 十四、能力边界与上线验收

### 14.1 当前不能替代的专业系统

- 无独立 APS 排产、产能日历和优化排程。
- 菲票是扎级追溯，不是逐件序列号。
- 质量能力包含节点检验、放行和轻量返修，但不是完整四段检验、AQL、缺陷树与不合格品处置系统。
- 仓储覆盖采购、暂收/IQC、批次、领退料与估值，不等于多仓、库位、盘点、调拨系统。
- 外发是轻量数量/金额跟踪，不自动生成应付或订单外发成本，不是完整委外三账。
- 财务已有应收、收款核销、采购应付、供应商付款、工资实付、其他收支和经营现金流，**不等于总账、税务发票或会计凭证系统**。
- 系统登记实付不表示已调用银行或微信支付，真实付款必须在外部渠道完成并核对流水。
- 云打印未接入；短信、微信订阅消息和真实 GLM 是否可用取决于部署配置和实网验收。

### 14.2 上线前现场验收清单

| 验收项 | 必做动作 | 通过标准 |
|---|---|---|
| 账号与权限 | 工人、仓管、跟单、车间、财务分别登录并切换公司 | 只能访问本厂和本人授权功能，直接链接也不能越权 |
| 真机扫码 | 摄像头、相册、手输、连续扫码、弱网、权限拒绝、污损码 | 菲票识别正确，无重复登记，待同步与服务端一致 |
| 蓝牙与出纸 | 每种手机/打印机组合测试连接、缺纸、断连、补打和偏移 | 实际出纸，内容完整、位置正确、另一台真机可回扫 |
| 完整生产链 | 隔离订单完成产前、采购IQC、开床、路线、交接、质检、包装、入库、出货 | 数量、余额、单证、库存和状态一致，审核不能绕过 |
| 一对多交接 | 一个交出目标分多个接收人，测试短少、多出、拒收、改派和超时 | 各单独立处理，批次可追溯，无超分或重复预占 |
| 客户资金 | 出货→应收→单笔/批量收款→撤销 | 金额、FIFO、余额和原始凭证一致 |
| 供应商资金 | 合格入库对账→应付→部分付款→作废→重新付款 | 应付余额、有效流水和经营现金流一致 |
| 工资资金 | 报工→结算→多结算分摊→实付→作废→重新支付 | 不超付，未付余额正确，原支付及分摊保留，现金流不重复 |
| 外部服务 | 真实短信、微信能力、语音识别、真实 GLM 分别测试成功与失败 | 有真实服务响应和可追踪结果；失败不伪造成功 |
| 导出与打印文档 | 打开 XLSX，打印本说明书或另存 PDF | 中文正常、表格可读、页码/导航符合实际工具输出 |
