# 第一部分 系统全景（目标态）

## 1.1 三层业务架构

```
┌─ 订单层（老板/跟单视角）─────────────────────────┐
│  订单：客户/交期/颜色尺码数量分解/整体完成度/交期灯    │  ← P1【新增】
├─ 执行层（厂长视角）───────────────────────────────┤
│  裁床：床次计划/编菲生成扎/锁定/裁完/菲票打印          │  ✅ + P2 向导化【改造】
├─ 计件层（工人视角）───────────────────────────────┤
│  扫菲：扫码→工序→登记→撤销；薪酬=快照结算             │  ✅ + P0 增强【改造】
└─ 支撑层 ────────────────────────────────────────┘
   组织权限 客户/工序/款式档案 仓库批次/追溯 看板(口径唯一+下钻)
   通知/审计/日志 设置(14开关)
```

## 1.2 核心主链路（数据流）

```
订单(颜色×尺码数量) ─┐
                     ├→ 建床向导 → 床次 Production(plan_qty,order,锁定,裁完)
款式(工序工价) ──────┘              └→ 菲票扎 Ticket(二维码,打印)
                                        └→ 扫菲登记 Record(qty×单价快照, qty_defect预留)
面料批次 Lot ←入库单                     │      ↓
   └→ 血缘 ProductionLotLink ←领料单     └→ 结算单 Settlement / 结算申请 SettleApply
                                              ↓
                                    看板（stats.py 唯一口径，全下钻）
```

**口径假设（写入设计，二期不动主体）**：登记量=合格量；qty_defect 为次品预留列，一期不消费，
未来加 quality 维度只改 stats 内部分子，口径主体不变。

# 第二部分 详细功能方案（11 域全量）

## 2.1 登录与多公司 ✅

- **登录**：手机号+验证码（60s 防重发/日 20 条）或密码 → token → 公司列表路由：无公司→创建引导；1 家→首页；多家→选厂页（显示岗位名）。微信登录（openid 关联）；token 过期自动登出。
- **创建公司**：名称（城市可选）→ 自动：公司编号（100001 起）、播种 3 系统岗位（管理员=`*`；裁床/车间=细粒度点集）、10 常见工序、14 项设置、默认看板模板 → 创建人为在职管理员。
- **加入**：扫公司二维码（`JOIN:` 前缀）或输编号 → 申请 PENDING → 管理员审核（容量校验：体验 20/基础 50/标准 150/旗舰 500）→ ACTIVE。重复申请 400、容量满 400。
- **切换**：我的→切厂 ActionSheet → switchCompany（last_used_at）→ 重拉全局+effective_perms。全接口 `X-Company-Id` 隔离。

## 2.2 组织与权限 ✅

- **岗位**：列表（管理员徽标/成员数/点标签）→ 弹窗：名称常用词点选 + 15 组 28 点勾选（`*`=全部）→ 保存。复制（"副本/副本2…"去重）；删除被成员 PROTECT 拦；系统岗位不可删。旧 coarse key 回显自动展开、保存落细粒度点，has_perm 永久兼容存量。
- **员工**：tab 在职/待审/离职 × 岗位 chips × 搜索；卡片置顶/⋯菜单（设岗位/设组/离职/复职）；邀请=手机号+姓名+岗位。离职有未结记录 400（force 可强离），离职薪可查；复职容量校验；指定工序 id 列表（决定扫菲工序选择器内容）；组编号 1~999。
- **判定**：has_perm（管理员或 `*` → 全过；细粒度直配；legacy 覆盖展开，高危点不覆盖）。effective_perms 随接口下发，前端按点显隐 + 后端 403 兜底。

## 2.3 公司设置 ✅

14 项 KV 开关：裁完自动标记〔决策：改纯人工，向导勾选〕、仅当月可撤、隐藏扫菲单价、过滤 0 数菲票、显示裁货总数、隐藏款式总单价、隐藏员工工资、未审核禁登记、默认计数开启、显示款式图、默认打印方式、云打印机、菲票标签样式、个性化通知。

## 2.4 基础档案 ✅

- **客户/分组**：编号自动 KH0001 顺延（软删防撞）、名称/电话/分组/备注；删客户 SET_NULL 不影响款式。
- **工序**：固定（全员可选）/非固定（指定工序）；默认单价（0 价合法存在但不可报工）；排序；建司播种；长按删除（被款式用/有登记拒删）；小程序可新建。
- **款式**：款号公司内唯一/名称/客户/图片（压缩存储）/备注；工序工价 `process_items[{工序,单价,排序,允许跳序}]` 保存自动汇总总价；复制（款号必改）；有床次引用删 400。〔近似工序模板：复制款式兜底，正式模板列二期（§八#10）〕。

## 2.5 订单管理【新增，P1 主体】

### 2.5.1 新建订单
单号留空自动 `SO`+4 位顺延〔决策，软删防撞〕→ 客户（可选）→ 交期（可选，有才有灯）→ 类型（自产/外发）→ 颜色×尺码数量矩阵（复用编菲矩阵交互：历史点选+自定义）→ 保存。落 Order+OrderItem；校验：同单同色码唯一、总数量>0。

### 2.5.2 详情与完成度
矩阵每格「订单数/已登记/完成率」，落后格（<80%〔决策〕）红底；汇总行整单完成率；交期灯（绿/黄=距交期≤7 天〔决策〕/红=过期未完成）。分子=挂单床次菲票登记按色码聚合（stats.py 唯一口径），分母=OrderItem.qty。关联床次列表点击跳详情；「＋开床」直达向导预挂本单。状态机：生产中→已完成/已取消（<100% 可完成，管理员知情操作）；满登记时提示一键标完成；已挂床次不可删只可取消。

### 2.5.3 挂单规则
可选挂单（散单/翻单允许无单开床；订单看板底部单列「未挂单床次」汇总）。挂单开床余量自动带出，**超订单剩余量弹「确认继续？」防手误不硬禁**。存量床次不回填；source_order_no 保留为外部单号（挂单自动带出）。

### 2.5.4 交期预警【新增，P3】
交期前 7 天站内通知管理员（复用通知模块）；过期未完成每日一条（按 单+日 去重）。

## 2.6 编菲/生产（P2 向导化【改造】，其余 ✅）

### 2.6.1 建床向导（4 步）
| 步 | 内容 | 要点 |
|---|---|---|
| 1 选单选款 | 有单从订单进（带客户+色码余量）；无单直接选款式 | 订单入口可跳过 |
| 2 裁剪计划 | 床次号预填最大+1 / plan_qty / 面料历史点选 / 来源单号 / **裁完自动标记勾选默认关** | 床次号公司内唯一 |
| 3 工序工价 | 带出款式工序价可逐条覆盖 | 0 价行警示 |
| 4 生成扎 | 颜色×尺码矩阵 + 扎号规则 + 起始扎号 → **实时预览「整除 N 扎+尾扎 M 件」再确认**【竞品细节】 | (床次,扎号)冲突自动顺延 |

每步校验不过禁下一步；挂单进入超量弹确认；成功页落床次详情并**引导打印菲票（可跳过）**【业界标准收尾】。存量无单路径字段顺序等价、不新增必填。

### 2.6.2 床次管理 ✅
列表（缩略图/进度/锁定/裁完筛选 + 锁床/裁完快捷开关 P2 提升至列表）；锁定拦该床全部菲票**新登记**（production.lock+审计）；裁完=纯状态人工标记；删除同事务级联软删菲票、有登记拦截；详情页瘦身（菲票列表/工序配置可改/追溯卡片/打印入口）。

### 2.6.3 加扎/打印 ✅
加扎=向导第 4 步矩阵（锁床禁加扎）。打印：单张/整床批量（分页护栏 5000）→ 预览（computeLabelLayout 同源）→ 蓝牙逐张（进度 x/N）→ print_count 回写；模板纸张/二维码大小/字段点选/每机偏移校准；断连入重试队列→打印管理补打。

## 2.7 扫菲（计件层 ✅ + P0 增强）

### 2.7.1 扫码登记
扫码/相册识别 → 解析 7 段码 → 校验本公司票 → 工序选择器（固定∪指定工序；单选项免选直达；0 价灰显「未上价」禁选）→ 数量默认整扎（同扎同工序全员累计≤扎数，超限拒绝；同人再登=增量累加沿首次单价快照）→ 成功反馈 → 连续扫码模式。
**P0 满扎提示**：选择器每个工序带「当前累计/扎数」（如 96/100），工人先看再登。

### 2.7.2 手输码兜底【新增，P0】
码破损/扫码失败 → 「手输查询」床次号+扎号 → 候选票列表 → 选中走同一登记流程。不新增权限点〔决策：复用 records.create〕；查询限本公司。

### 2.7.3 离线暂存 ✅+P3 增强
现状：请求失败自动入本地队列、onShow 自动补传（有自动化断言）。P3 可选：显式模式开关+暂存列表查看/手动重发。

### 2.7.4 撤销登记
本人当日撤自己（"仅当月"开关叠加）；撤他人=records.revoke（管理员岗恒过，写审计）；已结算一律不可撤；跨日修正找持点岗位代撤（路径已有）。

### 2.7.5 协助扫菲 ✅
登记选他人：须本公司在职（硬拦截）+ scan.assist 点 + 审计操作人。次品/返工：一期仅 qty_defect 预留列，闭环（双数量录入+返修单+次品率报表）列二期。

## 2.8 薪酬 ✅

工资 = Σ(登记 qty×单价快照) ± 工资调整 ± 固定工资。四次价格快照链（订单工序价→款式工序价→默认价→登记快照）改价不影响历史。**P0：工作台常驻「今日件数/今日预估工资」**（本人不受"隐藏员工工资"开关影响——该开关只管看别人）。结算单（salary.settle 按期间锁快照；撤结：与 PAID 重叠 400）；结算申请审核流（0→1→2/3/4 全程通知）；工资调整（salary.config±金额+事由+审计）。

## 2.9 看板体系（P0 下钻【改造】+ P1 订单层【新增】）

- **stats.py 口径唯一【改造，P0 地基】**：床次进度/款式行/订单完成度/范围汇总（完工=配满工序、在制=已登未满、已裁、登记）唯一实现；消费方=工作台/dashboard/计划表/款式页/订单页，改口径只动一处。
- **生产看板 ✅**：时间 6 档；汇总卡；计划表（款×色、真合并、块底交替）；近 7 天柱图；工序 Top6；员工/组排行。**P0 下钻**：模板 extra.link（白名单 production|ticket|order）→ 行 tap 预过滤跳转；**返回时保留筛选状态**【竞品细节：防"点进去丢上下文"】。**P1：订单列显示单号；「订单数量」列改名「菲票数量」**【名词统一，防与真订单量撞名】。
- **订单页签【新增，P1】**：看板页内 tab，订单卡片墙（完成率环形+交期灯+落后色码 chip+未挂单床次汇总）→ 点单进详情 → 床次。
- **配置端 ✅**：Vue3 列增删拖拽/公式/两级表头/真合并预览；P1 注册表补「订单」类目（单号/交期/完成率）。

## 2.10 仓库与追溯 ✅

采购单（draft→done，行=面料/色/量/价记录）；入库单行级批次诞生（公司+批次号 get_or_create，批次号=供应商原始编号）；领料单（draft→confirmed 确认钩子累加床次×批次血缘）；追溯四维反查（款式→床次、床次→菲票/批次/登记、菲票→血缘、批次→床次）；来源单号定位床次；历史血缘手工补录。

## 2.11 通知/日志/帮助 ✅ + P3

站内通知（join/审核/离职/结算/交期预警 P3）；操作日志（五类+before/after JSON，员工 scope=mine）；客户端日志（JS 异常/接口失败/埋点，厂隔离下钻）。**帮助页【新增，P3，纯文档】**：按角色三篇短指引（老板/裁床/车位），profile 入口，替代一对一培训。

# 第三部分 数据模型与 DDL（一次性迁移，2026-10-20 已批准）

```python
# apps/orders/models.py（新 app，避免模型冲突）
class Order(BaseModel):                      # 表 order
    company      FK Company CASCADE
    order_no     CharField(32)               # UK(company, order_no, condition=is_deleted=False)
    customer     FK Customer SET_NULL null
    delivery_date DateField null
    order_type   CharField(16) 自产/外发 default 自产
    status       CharField(16) producing/done/cancelled default producing
    remark       CharField(255) ''

class OrderItem(BaseModel):                  # 表 order_item
    order        FK Order CASCADE related_name='items'
    color        CharField(64); size CharField(32); qty PositiveIntegerField
    # UK(order, color, size, condition=is_deleted=False)
```

```python
# production/models.py 加列：order = FK('orders.Order', SET_NULL, null, related_name='productions') + idx(company, order)
# records/models.py 加列：qty_defect = PositiveIntegerField('次品数预留', default=0)   # 二期消费
```
