# 生产部署设计方案

> 2026-10-25。范围：单客户（汉川旭东）极简生产版；多租户规模化（容器编排/读写分离/对象存储）不在此层。
> 现状基线：settings 已全 env 化（SECRET_KEY/DEBUG/DB/CORS）；无任何部署制品；前端 BASE_URL 硬编码局域网 IP；本机无 Docker/WSL（本机只能做静态验证，实机演练在云服务器执行）。

## 1. 架构定案

```
微信小程序 ──HTTPS 443──▶ nginx ┬─ /api/  ──▶ gunicorn(127.0.0.1:8001, 3 workers) ──▶ PostgreSQL 15(本机)
                               ├─ /static/ 静态文件(collectstatic)
                               ├─ /media/  上传文件(视频/图片，磁盘)
                               └─ /healthz ──▶ gunicorn（升级断言/探活用）
```

| 决策 | 选择 | 理由 |
|---|---|---|
| 运行形态 | 裸机 systemd（非 Docker） | 本机无 Docker/WSL 无法构建镜像；单客户阶段裸机排障最直接；规模化再容器化 |
| WSGI 服务器 | gunicorn 3 workers × 2 threads | 单厂几十人扫码负载绰绰有余；threads 兜住上传慢请求 |
| 数据库 | PostgreSQL 15 本机 | settings 已支持 `DB_ENGINE=postgres`；SQLite 仅限开发 |
| Redis/Celery | **不引入** | 无异步任务/缓存需求；CONN_MAX_AGE=60 够用；引入即多一个运维面 |
| 证书 | Let's Encrypt（certbot --nginx）自动续期 | 零成本；小程序合法域名强制 HTTPS |
| 上传文件 | 磁盘 + nginx 直服 | 视频上传已上线（客户端 50MB 上限）；量大再迁 OSS（backup.sh 预留上传钩子） |

## 2. 硬前提（先于部署）

1. **域名 + ICP 备案**：小程序 request 合法域名要求 HTTPS + 备案，备案 1-3 周——**最先启动**
2. 小程序企业主体认证 + 「企业IT工具」类目
3. 隐私政策/用户协议（商用清单①，另办）
4. 服务器：2C4G 起步、磁盘 40G+（视频增长按月评估）、境内云（备案要求）

## 3. 安全加固（本次实现）

settings.py 增补（`DEBUG=0` 时生效）：SECURE_PROXY_SSL_HEADER、SSL_REDIRECT/HSTS（env 可调）、Cookie Secure、CORS 白名单化（**CORS_ALLOW_ALL 缺省值改为随 DEBUG**：开发 True、生产 False）；全环境：NOSNIFF + X-Frame DENY；新增 LOGGING（console + 滚动文件 logs/saofei.log 10MB×10）。`.env.production.template` 落全部生产值，SECRET_KEY 用 `python -c "import secrets;print(secrets.token_urlsafe(50))"` 生成。

## 4. 数据迁移：SQLite → PostgreSQL（首次上云一次执行）

`deploy/migrate_sqlite_to_pg.sh`：dumpdata（排除 contenttypes/auth.permission/sessions/admin.logentry，natural keys 保证 contenttype 重映射）→ 切 .env → migrate → loaddata → **行数对账**（逐 app 模型源/目标 count 比对，全等才通过）。**必须先在目标服务器演练一遍到演练库**（本机无 PG 无法预演），对账脚本可重复跑。

## 5. 备份与灾备

- `saofei-backup.timer` 每日 02:30 → `backup.sh`：在同一个 PostgreSQL 可重复读快照中执行 pg_dump -Fc 并生成全表行数/SHA-256 清单，另将 media 打 tar → `/var/backups/saofei/`，保留 14 天
- **异地一份**：填 `OSS_UPLOAD=1` + ossutil 配置即上传 dump、清单和 media（脚本已留钩子）；最低限度每周人工拷一份离机，dump 必须与同名 `.counts.json` 一起取回
- `restore_drill.sh`：先校验 dump 与清单匹配，再恢复到临时演练库，按**备份时点**清单对账全部 `public` 表并自动清理——**每月跑一次**（备份没恢复过=没有备份）。旧备份不与持续变化的活跃源库比较；第三个参数可传同名 media tar，额外在临时目录安全解压并逐文件核对 SHA-256

## 6. 发布与升级

- 首次：`deploy.sh`（装包/建库/venv/migrate/certbot/systemd enable 一步到底）
- 日常：`upgrade.sh` = **前置备份** → git pull → pip sync → migrate → collectstatic → restart → curl /healthz 断言；失败自动打印回滚指引并保留前置备份（不自动回滚代码——迁移不可逆时人工裁决）
- 迁移纪律（沿既有门禁）：migrate 前必有 makemigrations --check=0；破坏性迁移（删列/改类型）单独评审

## 7. 监控（极简版）

systemd Restart=always 兜进程；`/healthz` 供外部拨测（云厂商免费可用性监控即可）；logs/saofei.log 收 5xx/异常栈。告警接企业微信 webhook（拨测平台配置，非服务端组件）。

## 8. 前端发版

`utils/config.ts` 增加 `SAOFEI_ENV: 'dev'|'prod'` 开关——发布前切 prod（HTTPS 合法域名），开发者工具 cli preview/upload 走既有惯例。

## 9. 交付物清单（本次全部落盘）

| 文件 | 用途 |
|---|---|
| deploy/.env.production.template | 生产环境变量（含注释与生成指引） |
| deploy/gunicorn.conf.py | WSGI 进程配置 |
| deploy/nginx-saofei.conf | 站点配置（HTTPS/static/media/反代/50MB 上传） |
| deploy/saofei.service | 主服务 systemd 单元 |
| deploy/saofei-backup.{service,timer} | 每日备份定时单元 |
| deploy/deploy.sh | 首次上机 bootstrap |
| deploy/upgrade.sh | 日常升级（前置备份+健康断言） |
| deploy/backup.sh + restore_drill.sh | 备份/恢复演练 |
| deploy/migrate_sqlite_to_pg.sh | 数据迁移+行数对账 |
| settings.py / config/urls.py | 安全加固+LOGGING+GET /healthz |
| frontend/utils/config.ts | dev/prod 环境开关 |

## 10. 上机 Runbook（服务器端顺序执行，本机无法预演的步骤都在这）

1. 云服务器 Ubuntu 22.04 + 域名解析 + `bash deploy.sh`（交互式，含 PG 建库）
2. `bash deploy/migrate_sqlite_to_pg.sh`（先演练后真迁，行数对账全等）
3. certbot 签证书 → nginx 启用 → `curl https://域名/healthz` = ok
4. 小程序后台配 request 合法域名 → `SAOFEI_ENV='prod'` 切换 → cli upload 发体验版
5. 真机回归：probe 系列 + P1/P2 走查清单
6. 验证 `saofei-backup.timer` 首次触发产物 + 手跑一次 `restore_drill.sh`
