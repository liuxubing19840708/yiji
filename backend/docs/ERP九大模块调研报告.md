## 一、订单管理

**功能清单**
- MVP：客户/款号/颜色/尺码/数量/单价/交期录入（颜色×尺码矩阵是服装ERP第一特性，一款4色×5码=20个SKU）；订单查询与进度跟踪；订单关联BOM自动算料。
- 完整版：制板管理（板期规划、制板单、样板计价、打样进度）；成本预算与报价；订单评审（信用/产能/交期校验）；变更管理（色号改、交期提前、换供应商，服装订单碎片化下变更最频繁）；样衣全流程（头样/初样→跳码样→产前样PPS→船样，PPS必须用大货面辅料制作，确认后才能开大货）[^1][^4]。

**核心实体**：`sale_order`（单号、客户、下单日/交期、状态、金额、付款方式）；行 `items[]`：款号+颜色+尺码矩阵（qty按色码）、单价、工艺要求备注、指定面辅料供应商——交期/付款/指定供应商直接影响采购与排程，须随单携带。

**状态机**：录入→评审→已确认→(打样中→样衣客户确认)→生产中→部分出货→完货关闭；变更走审批留痕。

**上下游联动**：订单确认+BOM生效→MRP算料→采购申请；出货≤未交量校验；竞品建米订单管理覆盖制板/报价/接单/出货/报表五段，生产制单由板单自动开制（含款号/配色配码/图样/工艺/尺寸/物料清单/包装要求）[^1]——该论断经来源页面全文核对成立，佐证订单向导应自动携带技术资料。

## 二、技术管理

**功能清单**
- MVP：款式档案（款号、图片、工艺说明）；面料/颜色库（成分、克重、门幅、色号）；BOM（面料/里料/辅料+用量）；工序工价库（按款式设工序、定工价）。
- 完整版：BOM版本管理（版本错误曾致某企业10%订单返工、成本+15%）；取替代料；工艺单（尺寸表/公差、配色配码、排料、包装要求、箱唛、面辅料卡）；GSD工时定工价；BOM五分类（缩排式/汇总/反查/成本/计划）[^3]；预期呆滞料分析。

**核心实体**：`style`（款号、品类、季节、图片[]、工艺说明、状态：开发中/已确认/停产）；`bom(id, style_id, version, status)`；`bom_item(bom_id, 物料id, 类别, 净用量/单耗, 损耗率, 损耗后用量=单耗×(1+损耗率), 单位, 位置)`——经核对的实施指南明确要求**净用量与损耗率分列**、系统自动算含损耗采购量，单耗按样版排料图得出[^2]；物料档案建议"分类码+流水码+属性"编码，颜色/成分/克重用属性字段；工序字典 + `style_operation(style_id, 序号, 工序, 工价, 标准工时)`，工价表直接驱动计件工资。

**状态机**：BOM：草稿→审核→生效→（变更→新版本生效+旧版本停用+呆滞料预警）。BOM生效是MRP/采购计划的前置条件；华遨强调BOM准确性直接决定MRP采购计划准确性，版本管理与呆滞料、取替代件管理强相关[^3]。金蝶服装专版"一个款式一个BOM"处理配色配码、BOM可分版本[^7]。

**联动**：BOM行物料对应收料/入库/领料；工序工价驱动工票/计件工资（报工与工资挂钩后，某厂报工及时率从<60%提升到>95%）；成本核算从BOM引物料成本、从工票引人工成本。

## 三、采购管理

**功能清单**
- MVP：物料主档+供应商档案；物料需求汇总（BOM×订单数，对照现库存+在途→"采购空差"）；请购单；采购订单（从MRP导入勾选生成，支持并单/拆单、自动提示已购数量）[^1][^6]；到料登记（暂收+QC检验后正式入库）；PO交期跟催表。
- 完整版：询价比价、样品确认、供应商评级（合格率/及时率）；分批到货/溢短装；批次（缸号）管理+色牢度缩水率检测报告挂接；采购结算（货到立帐/票到立帐、预付/分期/冲销）；替代料；最小起订量与安全库存自动补货。

**核心实体**：`PurchaseOrder`（单号、供应商、状态、约定交期、总金额、来源MRP/请购单；明细：物料、颜色/缸号要求、需求量、已购量、单价、到货数、合格数）；`Receipt`（关联PO、暂收量、QC结果、合格入库量、缸号、检测报告附件）；`Supplier`（结算方式、评级）。

**状态机**：采购订单：草稿→已下达→部分到货→已完货→已结算（华遨五步闭环：采购计划制作→订单下达→收料→进度跟踪→结算，经来源原文核对成立[^5]）；到料：暂收→待检→检验通过入库/拒收退回。

**联动**：MRP毛需求−现库存−在途→采购计划→PO→到料通知→暂收+QC→入库产生应付；IQC不合格拦截入库投产。

## 四、仓储管理

**功能清单**
- MVP：面辅料/成品物料分类主档（幅宽、克重、颜色、缸号、单位、单价）；四种入库（采购/生产/外发回仓/其他）+四种出库（领料/销售/外发/其他）；调拨；库存余额/流水；最高最低库存报警[^6]。
- 完整版：盘点（空白盘点表、实盘覆盖账面、盘盈亏单）；月结；库龄/呆滞料报表；面料一物一码条码化（每卷布二维码：规格幅宽/克重/颜色/缸号/数量/供应商型号/来源单号，PDA扫码出入库）；同缸号出库控制（同缸优先同订单，并缸需色差确认放行）——经来源核对成立[^8]；辅料按工艺单定额管控、超领预警。

**核心实体**：`Stock`（物料+仓库+仓位+缸号+色差维度；数量、锁定量(已分配订单)、库龄）；`InOutOrder`（类型、来源单据、明细(物料/批次/数量)、状态）；`Stocktake`（范围、账面数、实盘数、差异、状态）。

**状态机**：出入库单：草稿→已审核→已过账（月结后锁定）；盘点单：编制→盘点中→差异确认→已调整入账。

**联动**：领料/实裁/退料三点把控；委外场景需跟踪外协厂物料发出/消耗/退料防超耗；成品入库→出货装箱单→应收。

## 五、生产计划

**功能清单**
- MVP：订单交期倒排的生产计划单；裁剪计划分床（按床次分配颜色×尺码比例、生成分扎表，对齐现有"扎"体系）；产能负荷粗平衡；计划变更与插单记录。
- 完整版：APS约束排产（设备状态、技能矩阵、面辅料到料、订单优先级，滚动刷新、插单连锁影响评估）；MRP物料净需求；裁床/排唛拉布比例与面料利用率（对接CAD放码）；班组计划与日派工单。行业实践：排产应随车间实际进展滚动刷新，插单时评估对整体交期的连锁影响。

**核心实体**：`production_plan`（plan_no、order_id、style_id、qty_planned、plan_start/plan_end、line/team_id、status、插单标记）；`cutting_bed`（bed_no、order_id、fabric_batch缸号、颜色×尺码比例JSON、层数、plan_qty、actual_qty、利用率）。

**状态机**：草稿→已下达→部分完工→完工→关闭；下达时联动生成裁剪计划与领料建议。

**联动**：销售订单审核→生产计划→MRP净需求→采购请购；裁剪计划→编菲打票→扫码产量登记→工资结算→完工入库。

## 六、生产管理（含外协）

**功能清单**
- MVP：委外加工单（工序/数量/单价/交期）、外发发料单、外发回货入库单、加工费对账；领料单（按BOM定额，超额预警）、退料单、在制品扎级台账；工票：裁床编菲自动分扎打票、扫码登记产量、计件工资=Σ登记量×工序工价、防重防超数。
- 完整版：外协发料回收明细管控（发出/消耗/退回三本账防超耗）；按交货+质量数据自动结算；缸号批次追踪+混裁拦截；WIP收发结存账（合格/废品/完工/未完工分列）；工票分配到班组防买卖工票、补飞/返工/掉飞特例、按车位×款式×工序单独定价（不回溯历史工资）、同床尾料编菲、对账清单与工资审核流。

**技术选型结论**：RFID电子工票可回收复用、可批量多读但需硬件投入；二维码菲票零硬件成本、票面可打印，是中小厂主流。二者数据模型同构（票=扎×工序），本系统现有二维码方案+手输兜底已对齐主流，**无需改道RFID**。吊挂EDI对接MVP不立项，仅预留产量登记来源字段（source: scan/hanger/manual）。

**核心实体**：`subcontract_order`（no、factory_id、order_id、工序ID列表、send_qty、received_qty、unit_price、amount、send_date/due_date/return_date、status）；`subcontract_material`（material_id、qty_sent/qty_used/qty_returned、batch_no）；`material_requisition`（qty_req定额、qty_actual、over_ratio、退料关联）；`ticket`扩展现有菲票（print_count原子计数、分配班组）；`output_record`增price_snapshot（登记时点工价快照，防工价调整回溯）。

**状态机**：委外：草稿→已审批→部分发料→全部发料→部分回货→全部回货→已结算→关闭（回货检验不合格走返工分支）；领料：草稿→已领→部分退料→结清；菲票：已打印→已分配→在制(locked)→完成→作废。

**联动**：委外单发料扣本厂仓、回货入WIP/成品仓、加工费挂应付；物料成本+计件人工+外协加工费汇聚成订单成本。

## 七、出货管理

**功能清单**
- MVP：出货信息登记（关联订单/客户/款色码/数量/日期/物流单号）；装箱单（箱号、款色码配比、毛净重、箱规尺寸）；每订单出货统计与未交量查询；交期预警（距交期N天未出货或生产滞后提醒）；出货单打印。
- 完整版：出货计划单（按客户/订单排出货窗口期）；逐箱码单明细；扫码装箱防错；船务单证管理（装船通知、报关面单、商检证、产地证套打）[^9]；客户对账单自动汇总；签收确认；负库存拦截。

**核心实体**：`Shipment`（单号、订单ID、客户、出货日期、状态、总箱数、总数量、物流方式/单号、审核人）；`PackingBox`（出货单ID、箱号、款号、色号、码数配比JSON、数量、毛/净重、箱规、箱唛）；单证记录（类型、模板、生成日期、打印历史）。

**状态机**：草稿→待审核→已审核→部分出货/已出货→已签收→已对账（可从已审核撤销回草稿）；ERP5装箱单流"已就绪→已运送→已接收→已交付"，数量不足时"拆分与推迟"自动生成余单[^10]——可采用部分出货自动拆单思路。

**联动**：出货审核扣减成品库存（负库存不允许出货）；出货数量≤订单未交量校验；出货确认自动生成应收。交期预警数据源=订单交期+面辅料到料日+车间进度；有案例用"面料到厂日+标准生产周期=预计出货日"最简测算，上线2个月准时交付率从约80%升至约95%。

## 八、质量管理

**功能清单**
- MVP：四类检验单（来料IQC、在制品中查/尾查IPQC、成品FQC、出货OQC）：关联采购单/供应商或订单/菲票，逐项结果+综合判定OK/NG，疵点登记（类型/部位/数量/等级/照片），不合格处置（返工/返修/退货/让步接收），返修登记与复检闭环，基础疵点统计。
- 完整版：AQL自动抽样（按GB/T 2828，服装常用致命0/主要2.5/次要4.0，按批量自动算抽样量与Ac/Re判定数）；面料四分制验布（接收线常见40分内）；疵点帕累托分析、PPM、批次合格率趋势；合批/跳检；逾期检验升级预警；分级让步审批流；供应商质量档案反向影响采购份额。

**核心实体**：`Inspection`（单号、类型IQC/中查/尾查/成品/出货、关联单据、抽样方案、检验员、判定、照片）；`Defect`（疵点类型：色差/布面/缝制/后整理四类；部位、数量、等级CR/MAJ/MIN、可修性）；处置单（返工/返修/挑选/特采让步/降级/退货、审批人、复检结果）。

**状态机**：待检→检验中→已判定→处置中（返修中/让步审批中）→复检→关闭；让步接收必须留书面审批痕迹。

**联动**：IQC不合格自动拦截入库投产；尾查/成品检验合格是成品入库和出货的前置条件；疵点数据反哺供应商考核与工艺改进（有面料厂上线8个月客诉降约4成）；返修回工位与菲票/工序流转联动。**MVP建议一个检验单实体带type字段覆盖四场景**，AQL抽样表静态查表即可。

## 九、财务与成本

**功能清单**
- MVP：订单实际成本=材料（仓库领料/耗用取数）+人工（菲票×工序工价取数）+制费（固定比例或工时分摊）——完工生产单从物料系统引材料、工票系统引人工、外发系统引发外成本，再加管理费用[^11]；报价/预算成本与实际对比出毛利；外协加工费结算（按合格交货数×单价生成应付）；单件成本与单件利润报表；计件工资按入库计件与按工序报工计件两种模式（鼎捷）[^12]。
- 完整版：共耗料分摊、在制品成本分摊、制费按工时/机器工时分摊、计划vs实际成本差异分析、月结与期初结转、业财税一体化（对接金蝶/用友总账）；应收应付：核销模式（预收/现款/分期/冲销）、客户信用额度控制、账龄分析、付款期限预警。

**核心实体**：`cost_order_cost`（order_id、material_cost、labor_cost、outsourcing_cost、overhead_cost、total_cost、output_qty、unit_cost、revenue、gross_profit、status：草稿/已核算/已结案）；`cost_entry`（source_type：material_issue/fee_ticket/outsourcing_settle/manual，建议从菲票、领料单、外发单三源自动生成+手工调整兜底）；`ar_receivable`（customer_id、order_id/shipment_id、amount、received_amount、status：未开票/已开票/部分收款/已结清/坏账）；`ap_settle`（bill_type：purchase/outsourcing/salary）。

**状态机**：应收：生成→开票→(部分)收款→核销结清→（异常）坏账；应付：立帐→付款→核销→调整。

**联动**：出货单→应收；采购/外发入库→应付；工资结算单→应付-工资；订单结案→触发成本核算并回写订单毛利。

## 十、整体数据流总图（文字）

```
客户订单(sale_order, 色码矩阵)
  → 款式档案 style + BOM(单耗+损耗率, 版本审核生效)
  → 生产计划 production_plan(交期倒排) + 裁剪计划 cutting_bed(分床/分扎)
  → MRP物料净需求(毛需求−现库存−在途)
  → 采购请购 → 采购订单 PO(并单/拆单)
  → 到料暂收 → IQC检验 → 面辅料入库(缸号批次) → 产生应付
  → 车间领料(按BOM定额, 超额预警)
  → 裁床编菲打票(扎=床×色码) → 扫码产量登记(菲票×工序)
  → 计件工资结算(工价快照) → 外协发料/回货(加工费挂应付)
  → 中查/尾查/FQC检验 → 成品入库
  → 出货单+装箱单(≤未交量校验, 部分出货拆单) → OQC → 扣成品库存
  → 自动生成应收 → 客户对账 → 收款核销
  → 订单结案 → 成本归集(材料+计件人工+外协+制费) → 回写订单毛利
```

关键闭环：①BOM生效是MRP前置；②检验合格是入库/出货前置；③所有入库产生应付、出货产生应收；④菲票计件数据同时驱动工资与订单人工成本。

## 十一、对已有菲票扫码系统的复用点

1. **票=扎×工序的数据模型已是行业同构主流**：与RFID电子工票、建米工票管理同构，无需改道；现有扫码+手输兜底保留。
2. **计件工资链路直接复用**：现有 salary 模块即"菲票×工序工价"，补 price_snapshot（工价快照）防调价回溯，即可同时作为订单成本的人工成本源。
3. **裁剪计划分床对齐现有"扎"体系**：cutting_bed 的颜色×尺码比例JSON、生成分扎表，与现有裁床/床次/满扎逻辑衔接，菲票状态机（locked/cut_done 由床次派生）无需重做。
4. **扩展字段少量**：`output_record` 增 source(scan/hanger/manual) 预留吊挂/人工来源；`ticket` 增 print_count（已对齐打印原子计数修复）与分配班组。
5. **质量模块天然打通**：中查/尾查关联菲票与床次，返修回工位走现有工序流转；与已有质量追溯模块（36用例）衔接。
6. **成本归集三源已具备两源半**：菲票（人工）、仓库（材料，需补定额领料）、外发（需新建委外单）——MVP做 `cost_order_cost` 汇总表即可见订单毛利。
7. **打印明细/补打**：现有打印历史+TicketPrintLog 可直接支撑出货单、装箱单、船务单证套打的复用。

**MVP优先级建议**（综合各角度共同结论）：先做"订单进度可视化+定额领料管控+订单成本汇总表+应收/应付立帐核销"见效最快，再攻APS排程、共耗料/制费分摊、AQL自动抽样与业财税一体化。
