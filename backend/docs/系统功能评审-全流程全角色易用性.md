# 系统功能评审：全流程拉通 × 全角色易用性

- 评审视角：专业服装行业从业者（车间实操 + 厂部管理双视角），只谈使用者"好不好用、顺不顺手"
- 评审对象：扫菲（衣计）小程序 + Django 后端，2026-11-02 代码现状
- 事实来源：全部结论基于代码核对（后端 17 个 app 路由、权限点 20 组 38 点、前端 55 页），不凭印象
- 对照竞品：**华遨软件**（广州华遨软件科技有限公司，2001 年起专做服装 ERP，1000+ 客户，官网 huaaosoft.com / cs-erp.com）——用户口中的「华傲」经 2026-11-02 联网核实为「华遨」，本文竞品列均取自其官网公开产品介绍（生产 ERP 专题页 + 官网首页），标注「华遨官网」。厂商未公开的深层功能（如一件一码/RFID/称重细节）官网未提及，不做臆断
- 术语：菲票=扎票（一扎一张条码票），床次=裁床排唛单位，开床=裁剪投产

## 一、执行摘要（10 条）

1. ✅ **一线车缝工动线已是行业第一梯队**：扫菲页常驻 tabBar 底栏、免登录直达、离线显式暂存、手输码兜底、满扎徽标——开班拿到手机 3 步内能登记。华遨同型产品为独立的「手机工票管理系统」（单独产品线），本系统把工票扫码内嵌为全厂 SaaS 的核心动线且配齐薪酬联动（华遨官网）。
2. ✅ **薪酬口径全系统唯一**（apps/salary/wage.py），已结/未结口径收编后，员工页、公司页、结算页三处数字不再打架；这解决了服装厂最频繁的劳资纠纷源头。
3. ✅ **计件价格三级链清晰**：床次价 > 款式工序价 > 工序默认价，且三个配置页都加了"谁优先"的白话说明（2026-10-29），新文员不用问人。
4. ⚠️ **通知只有站内，无外推**：交期预警靠 `notify_deadlines` 管理命令生成站内 Notification；微信订阅消息只做了引导项，模板未申请（profile 页 TODO）。老板不看小程序就收不到"快超交期"——这是当前最大的管理风险敞口。
5. ⚠️ **质量追溯入口被隐藏**：首页 `trace` 模块 `visible:false`（2026-10-22 用户要求），后端追溯 API 全部健在。功能在但看不见，客户投诉查责任时要临时开权限，动线断了。
6. ⚠️ **报价→订单→出货→应收全链已通，但收款后到成本归集是两条平行线**：应收核销与工资结算互不感知，财务要知道"这单赚没赚"得自己拿应收减成本页数字，没有单订单损益视图。
7. ⚠️ **多厂多仓缺失**：全系统单公司单仓（CompanyContextMixin 单 company；仓库为轻量单仓无库位）。一厂多车间分仓、面料/辅料/成品分仓的厂会撞墙。
8. ⚠️ **条码是"一票一码"（扎码）**：二维码内容为菲票码，扫码=整扎登记。吊挂/自动剪线类"一件一码"精确到件、以及计磅称重对接，均无（杰克吊挂 EDI 已调研未对接，风险点=扎件折算）。
9. ❌ **无生产计划/排产层**：订单确认后直接建床次开裁，没有交期倒排计划单、产能粗平衡、插单管理（P3 规划中）。目前靠厂长脑子排产，多单并行时优先级冲突无系统兜底。
10. ❌ **委外/外发流程空白**：发外工序（绣花、水洗、锁边）无外发单-回货单-加工费对账。外发件目前只能按普通扎走内部流程，回数对不上是常态（P3 规划中）。

## 二、全角色动线走查（8 角色）

> 步骤数为动线级点击/跳转次数估算；"痛点"均给出页面/字段证据。

### 2.1 老板/厂长

| 项 | 内容 |
|---|---|
| 主用页面 | 首页工作台、生产看板（六维 chip）、完成汇总、AI问报、通知 |
| 核心动线 | 看板 → 点维度 chip（订单/裁床/部门/组/人）→ 下钻订单详情/床次详情 ≈ **3 步** |
| 亮点 | ① 看板 `/dashboard/dim` 五维切换 + 完成汇总页并入五维视图（2026-10-23），一处看全厂；② AI问报（tabBar 第 6 项）自然语言问"哪些订单快到交期了"直接出表，行业里罕见；③ 首页常驻"今日件数/今日预估工资"两块数字，开屏即知产能；④ 交期灯 ≤7 天/已过期与订单列表同口径 |
| 痛点 | ① **交期预警不推人**（见摘要 4），老板必须自己点开通知页；② 看板数据接口无权限门槛（permissions.py:73 注释"当前全员可看"），员工也能看全厂产量——对按组计薪的厂是敏感数据；③ 没有手机端"老板日报"（昨日产量/今日待交/异常汇总一屏），要看 3 个页面拼 |
| 建议 | ① 订阅消息模板落地后，交期预警/异常扎直达推送；② 看板加 salary.view 类权限门槛或按岗脱敏；③ 通知页顶置"昨日日报"卡片 |

### 2.2 跟单/文员（订单+出货+报价）

| 项 | 内容 |
|---|---|
| 主用页面 | 订单管理、订单详情、报价三页、出货两页、应收三页、款式管理 |
| 核心动线 | 报价单 → 「转订单 ›」（quote-detail act 行）→ 订单页预填客户/款式/工序价 → 补色码数量 → 提交 ≈ **5 步**（2026-10-29 前：手工重录全部字段 ≈ 20+ 步） |
| 亮点 | ① 报价转订单预填含款式工序价行，且未挂款式时明确 toast 提示；② 订单颜色×尺码矩阵、复制行列（2026-10-23 P4）、款式多图 9 张、SO 自动号；③ 出货未交量校验 + 出货打印历史 + 云打印；④ 字段中文报错（P4），录错直接说人话 |
| 痛点 | ① 订单变更（改交期/改数量）无留痕页——客户扯皮时拿不出"谁什么时候改的"；② 出货单审核后改单要作废重来，没有"红字冲销"概念，文员怕操作；③ 报价转订单后两单无 FK 关联，报价改了订单不感知；④ 客户对账单（应收按客户月结汇总打印）没有，要靠应收列表筛选 |
| 建议 | ① 订单变更留痕（P3 已规划，建议提前）；② 应收页加"按客户汇总+账期"视图；③ 报价单加"已转单"状态戳 |

### 2.3 裁床/开床

| 项 | 内容 |
|---|---|
| 主用页面 | 生产管理、建床次（production-create 向导）、床次详情、打印菲票 |
| 核心动线 | 订单详情 → 建床次（颜色×尺码数量）→ 自动按 bundle_limit 拆整扎+尾扎 → 逐扎打票 ≈ **4 步/床** |
| 亮点 | ① 编菲自动分扎、扎号连续、尾扎预览（建单时能看到尾扎多大）；② 菲票蓝牙打印所见即所得（位图渲染 + 预览组件同源 computeLabelLayout），2026-10-29 修复字号不生效根因（labelBitmap 漏设 ctx.font）；③ 床次工序价建单时可逐条改，扫码即按此价；④ 完成度矩阵显示扎号不显示登数（2026-10-21），车间认扎不认登 |
| 痛点 | ① **打印依赖单台蓝牙打印机**，开床 300 扎要打 300 票，中途没电/断连无"断点续打"界面，只能重打（有回看补打但要逐扎找）；② 排唛/拉布比例、用料米数不在系统内——裁床用纸记录，领料按 BOM 定额但裁后实际耗用回不到系统（差异报表只有领料口径）；③ 锁床/解锁是高危点但确认只有一层弹窗，误锁会停一条线 |
| 建议 | ① 打票加"连续批量重打上次批次"一键；② 床次详情加"实裁米数"回填字段，喂给成本差异 |

### 2.4 一线车缝工（最核心角色）

| 项 | 内容 |
|---|---|
| 主用页面 | 扫菲页（tabBar）、工序页、我的薪酬、工作中 |
| 核心动线 | 底栏「扫菲」→ 摄像头对准菲票 → 弹确认（含工序/单价/件数）→ 确认 ≈ **2~3 步/扎**；手输码兜底再 +1 步 |
| 亮点 | ① 动线行业最短；② 离线显式暂存（断网不丢扎，恢复后提交）；③ 满扎徽标防超数（超限拒绝为准）；④ 登记后立即看到今日件数与预估工资（workbench my_today_amount）；⑤ 指定工序岗位（assigned）只显示自己的工序，杂工不迷糊 |
| 痛点 | ① **戴手套/强光/票脏污场景**：扫码失败率是行业痛点，手输码要切键盘输入 6-8 位，翻菲票找号慢，确认页字号中等——华遨官网未公开其确认页交互细节，语音报数/大字号为行业通行做法，建议按一线反馈决定；② 扫错别人扎（代扫）后撤销要走管理员（records.revoke 高危点），本人在"工作中"页只能看不能撤自己的错登（员工纠错动线断）；③ 换工序做同一扎（前道→后道）要重新扫码，一扎多道票面无"已做工序"勾选栏，靠记性；④ 计薪争议时员工端看不到"这张扎按哪个价算的"明细推导链 |
| 建议 | ① 确认页加大字号模式 + 语音报数；② 允许本人撤销 24h 内自己的登记（软撤，管理员可见）；③ 菲票布局加工序勾选列（templates.ts 排版已有竖排能力） |

### 2.5 后整/包装

| 项 | 内容 |
|---|---|
| 主用页面 | 扫菲页（后整工序）、出货装箱（shipment-detail） |
| 核心动线 | 后整登记同扫菲 ≈ 2~3 步/扎；出货装箱：出货单 → 加装箱 → 扫码/手选菲票入箱 → 打箱唛 ≈ **4 步/箱** |
| 亮点 | ① 装箱行按款色码配比校验，漏装短装当场拦；② 未交量视图（undelivered）直接列"该出没出的"，后整主任按单催活；③ 箱唛云打印 |
| 痛点 | ① 后整工序（剪线头/熨烫/检针）多数厂不按件计价而按天包工，系统 salary_type 支持日薪但"包工扎"（一扎打包价）不支持，实际在用变通；② 成品仓与出货未联动库存——出货审核不扣"成品入库"数（本无成品入库环节），账实核对靠盘点；③ 检针/验货不合格记录无独立模块，返修扎要靠备注 |
| 建议 | ① 支持扎级"包工价"（整扎一口价摊到件）；② 出货前生成"成品待入"虚拟入库或直接以出货为入库口径并明示 |

### 2.6 仓库

| 项 | 内容 |
|---|---|
| 主用页面 | 轻量仓库、暂收IQC、按床领料、供应商、需求汇总 |
| 核心动线 | 需求汇总（BOM×订单-库存=空差）→ 建采购 → 到料暂收+IQC → 确认入库 → 按床领料（超领 0 硬拦）≈ **5 环** |
| 亮点 | ① BOM 定额领料 + 超领硬拦 + 差异报表（P1），堵住了"随手多扯布"；② 需求汇总把多订单空差并单看，采购不漏；③ 供应商主档独立权限点；④ IQC 暂收与正式入库分离，符合来料检习惯 |
| 痛点 | ① **单仓无库位**：面料找货靠人脑记货架；② 退料是 type 字段而非独立单据，仓库月结对账不直观；③ 面料按"匹"管理缺失（缸号只在 lot 批次级），同缸裁验证（防色差）无系统拦截，靠裁床自觉；④ 出入库全部手工选物料，无条码（物料无一物一码），扫面料靠搜名称 |
| 建议 | ① lot 增加缸号字段并在按床领料时提示"本床已用缸号"；② 物料标签打印（库位码），为后续扫物料铺路 |

### 2.7 财务

| 项 | 内容 |
|---|---|
| 主用页面 | 应收管理、收款核销（receipts/receipt-detail）、库存估值、成本管理、工资结算 |
| 核心动线 | 出货审核 → 自动/手动建应收 → 收款核销 → 撤销/作废可控 ≈ **3 步/笔**；月结：库存估值 + 成本重算 |
| 亮点 | ① 应收核销/撤销/作废全套动作 + 移动加权库存估值报表（P2）；② 订单成本四同步 stale 钩子（领料/登记/制费变化自动标脏重算），成本不陈旧；③ 工资结算有申请-审核-发放-撤销全链，结算单锁定工资明细（防结算后偷改） |
| 痛点 | ① **无收款认领匹配辅助**：客户一笔款付多单，核销要逐单手配；② 无发票登记/税点字段；③ 成本页只有口径与材料+工资，制费分摊规则简单（按工时/件数直摊），接单报价时对财务口径成本帮助有限；④ 银行流水导入无（全手工） |
| 建议 | ① 核销页加"按客户未清应收余额"批量勾选；② 订单损益视图（应收-成本-未结工资预估）为最高价值报表（见摘要 6） |

### 2.8 系统管理员

| 项 | 内容 |
|---|---|
| 主用页面 | 员工管理、岗位权限（宫格按钮按点显隐）、公司信息、日志/客户端日志、打印管理、设置 |
| 核心动线 | 员工管理 → 建员工 → 配岗位（15+ 组权限点分组弹窗）→ 生效实时下发（effective_perms 随 post 下发）≈ **4 步/人** |
| 亮点 | ① 权限点 20 组 38 点分组渲染，高危点（删款/撤登记/结算）独立授权不随 legacy 继承——权限模型在同类小厂 SaaS 里属精细档；② 提权洞已修（Plan A 二期），客户端日志独立点；③ 打印管理可远程调字号/偏移/恢复预览，现场排障不用跑车间 |
| 痛点 | ① 岗位新建没有"复制现有岗位"，从零勾 38 个点；② 无操作审计的人性化视图（日志页是流水，不是"谁改了价"聚合）；③ 员工离职/转岗后历史菲票归属处理无引导（结算已锁，未结部分随人走易漏） |
| 建议 | ① 岗位"另存为/复制"；② 日志页加"改价/改工资"过滤器快捷项 |

## 三、全流程拉通矩阵（17 环节）

> 判定：✅ 自动带出 / 🔶 半自动（有联动但需手工触发或补录）/ ✋ 手工断点（纯手录，无系统联动）

| # | 环节 | 上游自动带出？ | 联动方式 | 对应页面 |
|---|---|---|---|---|
| 1 | 报价 | ✋ 新建报价 | 可挂款式带出工序价汇总 | quote-edit |
| 2 | 报价→订单 | 🔶 一键预填（2026-10-29） | orders?quote= 预填客户/款式/工序价，**无 FK 反向状态** | quote-detail → orders |
| 3 | 订单 | ✋ 录入色码矩阵 | 款式可带工序行；复制行列；SO 自动号 | orders（向导 2 步精简版） |
| 4 | BOM/定额 | 🔶 手动建 BOM | tech-boms 可关联款式；订单不自动展开 BOM | tech-boms |
| 5 | 采购 | 🔶 需求汇总并单 | demand-summary 按库存算空差，人工勾选生成 | demand-summary、suppliers |
| 6 | 到料入库 | ✋ 暂收→IQC→确认入库 | 三步链齐但无 PO 到料预警催跟 | receipts |
| 7 | 领料 | 🔶 按 BOM 定额预填 | 超领 0 硬拦；差异自动进报表；**触发成本标脏** | material-issue、issue-divergence |
| 8 | 裁剪/开床 | ✋ 建床次录色码数量 | 关联订单；bundle_limit 自动分扎 | production-create |
| 9 | 编菲打票 | ✅ 自动分扎+票面数据 | 齐套/床次价入票；蓝牙位图打印 | production-detail、cloud-printer |
| 10 | 扫菲登记 | ✅ 扫码带出扎+工序+价 | 床次价>款式价>默认价三级解析；**触发工资与成本标脏** | pages/scan |
| 11 | 尾扎处理 | 🔶 自动拆出尾扎 | 尾扎预览可见；尾扎单独票；无"并尾扎到别的床"收敛操作（待拍板项） | production-create |
| 12 | 完工 | 🔶 床次 cut-done 手动标记 | 完成度矩阵/五维下钻实时反映 | productions、completion |
| 13 | 出货 | ✋ 建出货单 | 未交量校验≤订单未交；装箱配比校验；审核后可打印上报 | shipments |
| 14 | 应收 | 🔶 create_receivable 共用生成 | 出货可带出应收（占位列待换真 FK 的遗留项已按设计保留） | receivables |
| 15 | 收款 | ✋ 核销 | 核销/撤销/作废全可逆 | receipts、receivable-detail |
| 16 | 成本归集 | ✅ 四同步 stale 钩子 | 领料/登记/制费变化自动标脏，重算出订单成本 | cost |
| 17 | 工资结算 | ✅ wage.py 唯一口径 | 已结/未结自动算；结算单锁定明细；申请-审核-发放-撤销 | salary/* |

**拉通结论**：登记之后的"产量→工资→成本"三线联动是系统最强项（全自动标脏+唯一口径）；登记之前的"订单→BOM→采购→到料"链条半自动环节多（4/6/7 处手工确认合理，但 2、4 处缺反查联动）；计划层（排产、插单、委外）整体缺位（P3）。
