## 第一章 杰克吊挂产品与数据架构

**产品与生态**〔官方〕。杰克 2019 年进军智能吊挂产业（与上海欧洛特合资成立浙江衣科达，官方 ESG 报告 2023/2024 大事记）。其吊挂定位为"成套智联"整厂方案的一环：面辅料仓储→智能裁剪→吊挂缝纫→后道分拣→成品仓储，配套自研 MES、APS、WMS、PDM，形成"北斗星"MoM 柔性智造管理系统，覆盖面辅料仓储、智能裁剪验布、裁片超市、AI 吊挂+AI 缝制、智能后分拣、成品仓储六大场景。公司持有"智能吊挂并行工序生产调度系统"软件著作权。英文官网明确："Jack supplies the hanging production system connected to the machine display and MES software"。

**数据架构**〔官方〕。最完整的公开描述来自杰克英文 IoT 手册：缝纫机/自动化设备内置 IoT 模块采集数据（加工参数、剪线次数、运行时长、故障码、软硬件版本等）→ 边缘/云 → 应用层（Jack House PC 软件、JACK APP、JACK MES V2.0：订单进度、扫码、工序管理、交期管理）。车间场景：吊挂+缝纫机操作屏+管理系统集成，每台缝纫机旁配平板终端，订单指令实时下发，实现拿/缝/挂工时精确计算、车工技能评估、设备上线率统计。技术底座早期基于中国移动 OneNET 物联网模式，后演进为 MQTT 边缘系统（边缘网关负责设备接入管理、状态检查、连接 IoT 设备与第三方软件、开发上传下载接口，支持本地化部署）。

**案例佐证**〔官方宣传〕。青岛瑞华：杰克成套改造后整体效率 +20%，最小订单 1 万件→1 件，生产周期 20 天→7 天；杭州杰克智联工厂（2022 年投产）全流程数据电子看板；杭州得体科技共享工厂项目；巴基斯坦 Shahkam Industries 宣称杰克智能吊挂与工厂自有 ERP "fully integrated"——注意此细节仅源于该方人员个人 LinkedIn 帖自述，无厂商技术文档佐证，应视为单方声明而非官方认证案例。

## 第二章 对接方式盘点（按可行性排序）

杰克官方 IoT 手册是唯一公开的对接级材料〔官方〕：当工厂**已有自有软件**时，杰克 "Provide cloud platform data API interface, support local deployment"，并列出三条通道——API（参数接口+状态接口，支持数据导入导出）、数据库共享（GST 数据库：剪线/抬压脚/针数/运行时长动作数据；APS 数据库：扫码与缝制运行数据；MES 与吊挂排产数据共享）、MQTT 边缘系统——三者均标注支持云端与局域网本地部署两种模式。据此结合行业通行实践排序：

| 路径 | 前提条件 | 工作量级 | 数据字段可得性 | 风险 |
|---|---|---|---|---|
| **1. 云平台数据 API**（官方承诺） | 杰克销售/实施渠道开通接口文档与授权（商务开通型，非开放平台型） | 中：接口联调+适配层开发，无公开规格需先索取 | 推断可得：工位扫码产量、工序流转、设备状态/参数、工时；字段粒度需项目确认 | 规格不透明、按项目收费、版本演进无公开变更通知 |
| **2. 数据库共享/中间库**（官方列出 GST/APS/MES 三类） | 工厂允许本方读库权限；杰克实施方开放 | 低-中：约定表结构后轮询即可 | 动作数据（针数/剪线/时长）与扫码缝制数据明确列出 | 实时性取决于轮询频率；表结构无公开文档；直连生产库需隔离只读 |
| **3. MQTT 边缘网关** | 本地部署场景，杰克边缘网关到位 | 中：订阅消息+解析 | 推断为设备/过站事件流 | 接口"开发上传下载接口"属定制开发范畴 |
| **4. 经厂内 MES 间接取数** | 工厂已上杰克 MES/北斗星，愿意开放对接 | 低：对接 MES 而非吊挂 | 订单/工序进度、扫码数量、欠数（杰克 MES 演示页有工序级欠数示例） | 多一层依赖；需与工厂 MES 负责人谈，非杰克总部 |
| **5. 上位机导出/文件对接** | 上位机 PC 可访问，人工或定时取文件 | 低 | 产量报表类，粒度粗 | 非实时；文件格式不公开；仅作兜底 |
| **6. 人工兜底（现有手输码流程）** | 无 | 零 | 按现有菲票口径 | 不实时、易错，作为任何方案的降级保底 |

**否定性结论**〔已核实〕：传统供应链意义的 EDI 报文（X12/EDIFACT 式）在服装吊挂领域不存在；行业语境的"EDI 对接"实为 API 直连/中间库/文件/工业协议的组合。"等杰克开放自助 API"不可作为主方案——第三方服装 SaaS 数加云联公示的可对接吊挂品牌（衣拿、圣瑞思、欧泰克、特高特、赫岱斯、明兴、ETON 部分型号）不含杰克（清单注明"其他型号请咨询客服"，留有商务口子）。杰克倾向自家 MES 闭环，对第三方 SaaS 是项目制联合开发而非开放平台。

**数据颗粒度要点**〔推断，多源交叉〕。吊挂是单件流：每个衣架带唯一 RFID 电子工票，数据粒度=一件×一道工序×一个员工；返修表现为同一衣架 ID 重复过站+质检事件标记，产量区分合格数与返修次数。这与菲票"一扎"颗粒度不同（杰克吊篮线 HS6-D/HL6-D 一篮多件可近似扎粒度），**必须自建扎↔件映射层**。断网续传机制无杰克官方说明，需按"事件流+幂等去重"自行设计。

## 第三章 对本 SaaS 的落点

**推荐实现路径**：优先谈**云 API（参数+状态接口）**，本地部署客户备选 **GST/APS 数据库共享（中间库轮询）**。落到现有设计（设计方案 §4.7）即：

```
杰克吊挂 →（云API轮询 或 中间库只读轮询）
  → EDI网关适配层（字段映射+扎↔件折算+合格/返修口径归一）
  → 以 source='hanger' 写入产量登记
  → 复用现有防重/超数校验
```

网关侧需三个关键设计〔推断〕：
1. **幂等**：以"衣架 ID+工序+过站时间戳"为去重键，应对断网补传重复。
2. **单位与口径契约**：件↔扎折算规则、合格品 vs 实际产出+返修数，在契约层显式转换，匹配失败进异常表人工处理（不能静默丢弃）。
3. **下发链路**：订单/工序/扎号/目标量是否下发需与杰克确认——若杰克 MES 已持有工单，本 SaaS 可只做回传侧，定位为"与 Jack MES 平级的数据汇系统"。

**设备/工位映射建议**：建立"杰克工位号/衣架 RFID → 本 SaaS 工位+员工+工序"映射表，员工卡绑定关系随报文核验；工位级事件（到达/离开/合格/返修）落原始事件表，登记表只存折算后的扎级产量，保留追溯能力。

**若杰克无公开 API 时的谈判要点**（向杰克销售/实施方索要清单）：
1. 云平台数据 API 的 endpoint、鉴权方式、参数/状态接口的字段字典与调用配额；
2. GST/APS 数据库共享的表结构文档与只读账号；
3. 本地部署 MQTT 边缘网关的 topic 定义与报文样例；
4. 是否支持"工厂已有第三方 SaaS"的既有交付案例可参考（引用 Shahkam 等案例作为商务筹码）；
5. 接口开通费用与交付周期（属工程实施级，无公开报价）。

**并行务实策略**：若客户尚未采购吊挂，推荐清单应把明兴 CleverMax（唯一公开写明"REST+OPC-UA 对接、已连 SAP/金蝶/用友"的厂商，但其规格为厂商自述）、圣瑞思（瑞晟智能 688215）、衣拿列入优先——对接成本最低；若客户已上杰克北斗星/MES，对接 MES 而非直连吊挂。

## 第四章 结论与开放问题

**结论**：杰克吊挂存在成体系的对第三方数据出口——官方 IoT 手册明示云 API（参数+状态接口+数据导入导出）、MQTT 边缘系统、GST/APS/MES 三类数据库共享，均支持本地部署；且存在与工厂 ERP 集成的公开案例。对接真实可行，但属**商务开通型项目制**而非开放平台自助接入：接口规格、费用、周期均需经杰克销售/实施渠道获取。对本 SaaS 的落地形态即"EDI 网关轮询 API 或中间库→适配为 source='hanger' 登记→复用现有校验"，最大技术风险不在通道而在**扎↔件颗粒度折算与返修口径归一**。

**公开渠道未查到**：①任何字段级接口规范（endpoint/鉴权/报文字段表）；②吊挂主机公开型号谱（缝纫机有 JK 型谱，吊挂线无）；③断网续传机制说明；④具体时延指标（行业对照：明兴宣称单网关 5 万条/秒、端到端 100ms 内，为厂商自述）；⑤接口商务报价。

**需向杰克官方确认的清单**：①客户版本吊挂是否默认含 IoT 模块与边缘网关，旧线改造范围与电控兼容风险；②云 API 开通流程、文档获取条件、是否有标准对接包；③三类数据库共享在本客户工厂的实际可用形态（云端/局域网）及表结构；④下发能力边界：订单/扎号/目标量能否由第三方下发，还是仅杰克 MES 持有；⑤返修件数据格式；⑥已有第三方 SaaS/ERP 对接的参考案例与责任边界。
