## 二十二、工人端信任补齐（工价拦截 · 相册补扫 · 变更透明）

> 来源：需求调研-续.md §8.3 用户差评痛点（栢顺 2.4 分 / 金鹏差评交叉印证）与 §8.5 差异化启示 #3。
> 定位：竞品最大的洼地是「工人不信任」——本切片把三条直击差评的能力补齐，使其从调研结论变成产品验收项。

### 22.1 工价未配置拦截（痛点 #2：「厂里经常没有上单价，即使扫了也是没钱的」）

**功能需求**
- 登记链路三道关卡，保证系统里**不存在静默的 0 元流水**：
  1. **扫码环节（事前提示）**：工序选择 chips 上，单价为 0 / 未配置的工序显示红色「未上价」角标且**不可选**；若该菲票全部工序都未上价，显示整卡提示「该菲票工序尚未配置工价，请联系管理员」
  2. **报工环节（事中拦截）**：后端解析出的登记单价为 0 时拒绝登记（400），错误文案「工序【X】尚未配置工价，请先在工价管理中设置」；协助扫菲（管理员代登）同样拦截，不给绕行
  3. **编菲环节（源头预检）**：工序配置保存允许 0 价（质检等不计件工序合法），但裁床编菲预检发现所选工序存在 0 价时弹确认「存在未上价工序，登记时将无法计件，继续？」
- 工价后补不丢数据：拦截只挡新登记；工价配置后该菲票立即可正常登记，历史拦截不产生任何残留

**实现逻辑**
- 后端 `records/views.py` `_resolve_price`（现三级回退：床次订单工序价 → 款式工序价 → 工序默认价）末尾增加判定：`price == 0 → raise ValidationError`，文案带工序名；`Process.default_price` 与配置价允许 0 的现状不变（0 价合法存在，只是**不可被报工**）
- 扫码页 `process-selector` 返回的 price 前端已知：chip 渲染时 `price === 0` → 加 `disabled` + 「未上价」角标；全 0 → 空态提示，不出件数确认页
- 编菲预检：`production-create` 提交前检查所选 `process_items` 中 price=0 的项，`wx.showModal` 确认后才提交（不阻断提交，只阻断无感知）
- 验收标准：0 价工序扫码 → chips 灰显角标；强行 API 报工 → 400 带工序名；配置价格后 → 立即可登记

### 22.2 相册选图补扫（痛点 #6：「为什么不添加相册内选择图片？」）

**功能需求**
- 扫菲页扫码态增加「从相册识别」按钮（与相机取景框同级，弱化样式）：点击拉起系统相册，选中含菲票二维码的图片后自动识码，进入与扫码完全相同的解析管线（菲票卡 → 工序 → 件数确认）
- 覆盖场景：菲票二维码破损扫不进、车间扫码灯光线差、菲票是照片打印件、补录昨天的菲票
- 识别失败（图片无二维码）toast「未识别到菲票二维码，请对准二维码拍摄」，停留在扫码态

**实现逻辑**
- 零新依赖：`wx.scanCode({ onlyFromCamera: false, sourceType: ['album'] })` 原生支持相册选图识码，成功回调返回的 `result` 与相机扫码同构，直接复用现有 `parseScan → state=process` 管线
- 按钮放置于扫码态取景框下方；协助模式下同样可用
- 验收标准：相册选菲票图 → 解析出菲票卡且扎号正确；选无码图片 → toast 且不跳转

### 22.3 员工端变更透明（痛点 #3：「厂家可以后台修改我们的件数」「文员没经我同意就能删菲」）

**功能需求**
- 员工可随时查看**与自己相关的全部变更记录**：谁在什么时候把我登记的件数/单价改了、谁撤销了我的登记、谁替我代登过
- 入口：「我的」页新增菜单项「与我相关的变更」→ 独立列表页（样式复用操作日志页）
- 记录范围：审计日志中 `target_user = 本人` 或 `operator = 本人` 的记录（含修改价格/协助登记/修改裁床数/撤销登记四类）；展示字段：类型徽标 + message（服务端插值后的完整文案）+ 时间
- 边界：仅可读，不可筛选他人；管理员原有的全量日志管理页不受影响

**实现逻辑**
- 后端复用 `AuditLogListView`：新增 `scope=mine` 分支——不走 `require_admin`，查询条件改为 `Q(target_user=request.user) | Q(operator=request.user)` 且 `company=request.company`；`scope` 缺省维持管理员语义（两分支互不影响）
- 前端：`services/ops.ts` 的 `fetchAuditLogs` 增加 `scope` 参数；新页 `packages/profile` 下或复用日志列表组件，菜单项仅员工显示（管理员已有「日志管理」全量入口）
- 数据无需新增表：审计日志本就按 §十四 规范服务端插值落库，工人端透明化是**同一份数据的可见性开放**，这是把审计从合规功能变成信任卖点的设计落点（§8.5 #2）
- 验收标准：管理员改某员工工序单价 → 该员工「与我相关的变更」立即出现「修改价格：…¥0修改成¥8.5…操作人：X」；员工看他人记录 → 接口只返回与自己相关的
