# 衣计 ERP Web 工作台

Vue 3 + Vite，复用 Django `/api`、JWT 与 `X-Company-Id`，业务计算、权限和状态约束仍由后端负责。

```bash
npm install
npm run build
```

构建输出至 `backend/static/web`，由 Django 在 `/web/` 同源托管。开发时运行 `npm run dev`，默认把 `/api` 代理至 `127.0.0.1:8000`。

密码、短信验证码和微信网页 OAuth 共用公司选择流程。微信网页登录由部署方配置 `WECHAT_OPEN_APPID` / `WECHAT_OPEN_SECRET`，并在微信开放平台网站应用中登记实际 `/web/` 所属授权回调域；未配置时按钮明确禁用。小程序 openid、Web openid 分开保存，仅通过微信 unionid 关联同一主体。

## 已实现模块

- 现场工作：工作台、相机/相册/单扎扫菲、按公司隔离的离线幂等队列、语音报数、批量/协助登记、计件改数与撤销、通知、AI 语音问报。
- 生产协同：订单创建/编辑/流转/审计，四步产前准备与工艺模板，开床、编菲、床次工序、锁定/裁完、面料批次挂接、通用责任交接、出货与装箱、质检、委外。
- 经营管理：工资汇总与调整、结算申请/审核/发放、工资实付与结算分摊、薪资条、应收财务、采购应付、供应商付款、其他收支、经营现金流、成本、报价。
- 基础与系统：物料、BOM、采购、暂收/IQC、入库、领退料、需求差异、批次追溯，款式/工序/客户档案，员工/岗位/工资制，公司与系统设置。
- 文件能力：物料/BOM/期初库存 `.xlsx` 导入，质检/委外等 Excel 导出，款式图片、工艺图片及工艺视频上传。
- 打印能力：菲票、出货单和装箱单预览；浏览器打印须由用户确认实际成功后上报。支持 Web Bluetooth 的真实菲票选择、中文整签位图、二维码、失败队列与重试；蓝牙写入只记为待现场确认，不自动增加业务打印计数。

桌面和手机使用不同导航与记录布局，浏览器前进/后退可切换模块。

## 微信小程序布局对齐

手机端按小程序逐页实现橙色顶栏、今日件数与今日预估工资、日期区间条、管理员七组三列宫格和普通员工“工序 / 我的薪酬 / 工作中”单组，以及“首页 / 扫菲 / 中央凸起 AI 问报 / 通知 / 我的”底部导航。“我的”提供个人资料、工厂切换、全部功能、退出登录；32 个独立入口直接到达对应页面或业务页签，刷新后仍保留位置。

订单、生产、扫菲、批量、薪酬、通知、计件记录、仓库及经营管理页使用各自的小程序页签、筛选、独立业务卡、详情和任务表单；支持加载更多的页面保留首屏错误、追加错误重试、空态和没有更多状态。桌面端保留侧边栏、25 个工作区和完整 ERP 写操作，不用移动卡片替代桌面多列工作区。

## 浏览器回归

无需后端或真实设备的账号、产前、交接和设备等价能力 mock 回归：

```bash
npm run test:e2e -- e2e/account-auth.spec.js e2e/preproduction-handover-parity.spec.js e2e/device-parity.spec.js
```

这些用例核对真实控件、请求方法/载荷、离线幂等号、语音识别结果复核、中文菲票位图及 BLE 分包写入；不会访问真实公司、微信、短信服务或打印机，也不代表物理设备已验收。

真实隔离环境回归不提供默认账号：

```bash
# Windows 可设置 CHROME_PATH 指向本机 Edge/Chrome；否则先安装 Playwright Chromium
export WEB_BASE_URL=http://192.168.10.16:8000
export WEB_PHONE=隔离测试账号
export WEB_PASSWORD=隔离测试密码
npm run test:e2e
```

AI 问报完整回归需要同一隔离库的导出 worker，并显式设置 `WEB_AI_WORKER=1`：

```bash
python manage.py process_ai_exports --poll 1
export WEB_AI_WORKER=1
npm run test:e2e -- e2e/ai-report-designer.spec.js
```

该文件覆盖真实隔离登录下的查询、导出、图表、分享、定时任务创建/启停/删除，以及不连接数据库的期间对比和定时任务模拟交互。模拟用例也需要设置占位 `WEB_PHONE/WEB_PASSWORD` 以通过统一测试门槛，但不会向认证接口发送这些占位值。`e2e/ai-schedule-run-center.spec.js` 另以纯 mock 覆盖移动端运行中心的手动执行、失败重试、刷新、加载/空/错误态，不连接业务数据库或 GLM；通知仅提供查看入口，不展示业务结果、行数或筛选值。

```bash
# 真实隔离后端：统一经营现金流数据集执行与 XLSX 导出
npm run test:e2e -- e2e/ai-cash-flow-live.spec.js
```

资金操作界面回归：

```bash
# 真实隔离后端：应付、付款及余额回退、收支、现金流、无结算工资实付与作废
npm run test:e2e -- e2e/cash-operations-live.spec.js

# 全 API 模拟：超额付款、重复提交、必填原因、权限错误、移动卡片和结算分摊
npm run test:e2e -- e2e/finance-cash.spec.js e2e/salary-payments.spec.js e2e/salary-mobile.spec.js
```

真实资金用例会保留已作废流水作为审计事实，不调用删除接口；必须只指向可丢弃的隔离数据库。结算分摊与超额付款等场景由全 API 模拟用例覆盖，真实隔离库没有相应已认证结算数据时不会伪造该业务事实。

基础与生产写链路覆盖：

- 桌面/手机登录、25 个工作区逐页渲染、接口状态、床次详情、真实菲票查询，以及 320/360/390px 页面横向溢出。
- 32 个首页入口逐一点击并校验目标页签、普通员工单组、五区底栏、中央 AI 按钮、“我的”和全部功能。
- 12 类新建/编辑弹窗的顶部、滚动到底部后的主要操作及关闭流程；薪酬移动员工卡、完成矩阵、薪资条和桌面原写链路选择器。
- 订单创建 → 关联开床 → 工序继承 → 编菲 → 二维码预览 → 锁定/解锁 → 扫菲登记 → 撤销 → 删除床次 → 完成并删除订单。
- 写链路监听真实接口响应，并在 `finally` 中清理测试记录。

扩展测试还需要后端 Python（用 `openpyxl` 动态生成真实 XLSX）：

```bash
export WEB_PYTHON=/path/to/backend/.venv/Scripts/python.exe
# 上传测试默认清理 backend/media 下本次生成的随机文件；自定义部署可设置：
export WEB_MEDIA_ROOT=/path/to/backend/media
npm run test:e2e -- e2e/extended-features.spec.js
```

扩展测试覆盖真实物料/BOM/期初库存 XLSX 导入、床次挂批、质检/委外 Excel 下载、出货建单与装箱、出货单/装箱单预览及打印上报、款式媒体上传与保存。

复杂写链路可单独运行：

```bash
npm run test:e2e -- e2e/complex-write-chains.spec.js
```

覆盖批量登记部分成功/部分失败及逐扎数量、金额和失败原因；工资申请、审核、发放、结算单、记录圈占和薪资条；采购单创建、草稿单头编辑、确认完成，以及终态页面和接口双重只读。

**扩展与复杂写链路测试应指向可丢弃的隔离数据库副本。** 期初入库、出货打印日志、工资发放结算单和已确认采购单属于正式业务留痕，不能为了测试而提供删除接口；测试结束后直接废弃副本。媒体上传测试只验证上传、路径保存与清理，不代表所有手机/浏览器的视频编码兼容性均已验证。

## 使用边界

- 浏览器相机和相册扫码依赖 `BarcodeDetector`，通常需要 HTTPS 或 localhost；不支持时可粘贴二维码内容，或按床次号与扎号查询。
- 离线登记只保存在当前公司、当前用户和当前浏览器，只有网络失败才入队；补发使用同一个服务端幂等键，HTTP 业务拒绝不会伪装成离线成功。
- AI 语音识别、语音报数和 Web Bluetooth 依赖浏览器及操作系统支持；不支持时显示明确原因，不伪造识别或打印成功。
- 中文菲票蓝牙打印为 203 dpi TSPL 位图实现；具体打印机、纸张、字体、极性、走纸和回扫仍须现场验收。
- 浏览器通知与微信订阅消息是不同通道；真实短信、微信 OAuth、云打印、手机相机和实体打印均需另行实网/真机验收。
